> 3. **연구노트 상단 레퍼런스 추가 모달 (`NoteReferencesModal`)**: 저장된 연구노트의 상단바에 클립 아이콘만 두고 hover/focus 시 `레퍼런스 추가`를 안내한다. 클릭하면 Wiki 서고 선택, 새 파일 업로드, 웹 URL 추가, 다른 연구노트 스냅샷 가져오기의 4개 탭이 열리며, 사용자가 `적용하기`로 확정한 자료만 현재 버전에 연결한다. 상시 선반 바와 셀렉트 박스는 노출하지 않는다. `[이 버전을 Wiki에 등록]` 아이콘은 현재 검증된 연구노트 버전을 Wiki 서고에 불변 스냅샷으로 발행한다.
> 4. **제로베이스 에디터 인라인 레퍼런스 검색 드로어 (`NoteInlineSearchDrawer`)**: 연구노트 작성 중 단절 없이 즉시 조회할 수 있는 에디터 인라인 검색 드로어를 신설했다. `[● 이 노트 레퍼런스만 (N개)]` vs `[○ 전체 Wiki 서고]` 스코프 토글을 지원하여, 이 노트에 묶인 자료만 핀포인트로 검색하거나 전체 서고를 폭넓게 탐색할 수 있다. `[인용문 본문 삽입]` 버튼 클릭 한 번으로 에디터 현재 커서 위치에 마크다운 인용 블록(`> "..." — *출처: ...*`)을 자동 삽입한다.

## 기본 사용 흐름 재정렬

RAG·그래프·Wiki는 사용자의 첫 입력 양식이 아니라 문서 분석을 돕는 내부 계층이다. 기본 순서는 문서 저장, 실제 전송 범위와 모델 확인, AI 후보 분석, 원문 인용과 함께 결과 확인, 사용자 수정/채택, 새 버전 재검사다. ResearchContract 수동 입력과 그래프 관계 승인은 선택적 상세 작업이다. 저장된 문서의 블록/hash는 자동으로 만들 수 있지만, AI가 추출한 가정·정의·주장과 관계는 `제안`으로 구분하고 승인 없이 정본 연구 기준이나 외부 증거로 승격하지 않는다. Wiki는 이 상태와 출처를 보여 주는 파생 뷰다.

새 문서의 첫 화면은 제목·본문·저장에 집중한다. AI 분석과 연구 기준 후보는 저장 후 별도 단계로 열며, 저장 자체는 모델 호출이나 RAG 색인 요청을 시작하지 않는다. 저장 후 상단바의 즉시 동작은 AI 분석·저장으로 제한하고, 연구 기준은 편집 도구줄, 버전 비교는 버전 표시에서 연다. 프로젝트 관리 메뉴와 관련 신규 기록 생성은 제거했다. 출처·전송 승인·검토 판정 계약은 유지한다.

문서 저장 성공 상태 배너는 4초 뒤 자동으로 해제된다. 이 표시 수명은 정본 버전·RAG 자료 범위·오류 표시 계약을 바꾸지 않는다.

가운데 문서 미리보기의 읽기 폭·제목·KaTeX 표시 수식 스타일만 정돈했다. 원문 Markdown, 버전/hash, 문서 블록화, 전송·RAG 범위는 변경하지 않았으며 긴 수식은 해당 영역에서 가로 스크롤한다.

미리보기 전용 MathJax SVG 시험 선택지를 추가했다. 기본은 KaTeX이고 MathJax 번들은 선택 시 로컬에서 불러온다. 두 렌더러 모두 같은 원문 Markdown과 기존 LaTeX 전처리 결과를 표시할 뿐, 문서 정본·버전·근거·전송 범위를 변경하지 않는다. 렌더러별 수식 지원 차이와 긴 문서 성능은 후속 평가가 필요하다.

현재 구현은 이 중 기본 화면의 저장·AI 분석 진입/전송 승인과 기존 검토 결과/수정 버전 기록을 잇는 초판이다. 전체 문서가 40 KB 검토 요청을 넘으면 명시적으로 범위 계획을 세워야 하며, 자동 장문 배치·구간 간 의미 종합·자동 그래프/Wiki 후보 저장은 아직 아니다. 다음 구현에서는 첫 분석에서 빠진 범위를 숫자와 원문 위치로 보여 주고, 여러 요청·비용을 승인받아 전 범위를 다루며, 주장/관계 후보의 출처·상태를 저장해야 한다. 일반적인 정합성이나 이론의 참을 자동 확정하지 않는다.

로컬 자료 이동의 첫 단계로 명시적 폴더 선택을 통한 작업공간 JSON 백업과 현재 연구노트 버전의 별도 Markdown 폴더/manifest 내보내기를 추가했다. Markdown은 읽기 편한 사본이며 정본/근거/과거 이력의 복원 형식은 JSON 백업이다. 이는 RAG 색인이나 근거 정책을 변경하지 않으며, 선택 폴더에서 원문을 자동 읽거나 모델에 보내지 않는다. 외부 수정 감지·양방향 동기화·실제 폴더 권한 테스트는 아직 없다.

저장소 루트의 `./run.sh`는 로컬 Vite 실행 편의 스크립트다. RAG 검색·근거 선택·LLM 전송 승인 정책을 바꾸지 않으며, `.env.local`의 키를 브라우저에 자동 주입하지 않는다.

연구노트의 기본 구조 확인 결과와 AI 검토 결과를 화면에서 분리한다. AI 분석은 저장 후 주 흐름에 두고, 기본 구조 확인은 의미 분석이 아님을 밝히며 선택적 상세 설정에 둔다. 빈 ResearchContract 필드는 선택 입력 안내 하나로 묶는다. 모델에 보내는 문단·연구 기준은 원문 중심 미리보기로 표시하고, 스키마·hash·ID가 포함된 원시 요청은 접힌 기술 정보로 유지한다. 이는 전송 승인과 감사 가능성을 보존하면서 내부 저장 형식을 일반 사용자 결과처럼 노출하지 않기 위한 표시 계층 변경이다.

연구노트 화면의 기본 경로는 문서 선택·편집·저장·검토다. 관계/Wiki는 상세 검토에서, 버전 비교는 버전 표시에서 연다. 프로젝트 자료 정책·외부 주장 원장 메뉴와 정책 변경·주장 채택/연결은 더 이상 제공하지 않는다. 기존 정책은 과거 기록 및 전송 범위의 무결성 보호를 위해 읽기 전용으로 적용된다.

ResearchContract의 AI 후보 생성은 제목·본문을 사용자가 먼저 확인하고 명시적으로 제공사에 보낸다. 모델이 반환한 필드별 제안은 원문에 정확히 있는 인용이 동반될 때만 보여 주고, 사용자가 체크한 필드만 초안에 반영한다. 인용되지 않은 가정·정의·범위를 자동 채우거나 자동 저장하지 않는다. 출처 문자열 일치는 후보 필터이며 의미적 정합성 검사가 아니다. 자체 문서의 후보를 외부 증거로 승격하지 않는다.

긴 정본 초안은 40 KB 요청 한도를 문서 전체 거부 사유로 삼지 않는다. 본문을 빠짐없이 순서 있는 요청 구간으로 나누고 모델·구간 수/원문·요청 횟수·제외 구간 없음 여부를 전송 전에 확인한다. 각 구간의 후보는 해당 구간 또는 제목의 정확한 인용으로 검증하고 필드별 첫 유효 후보를 합친다. 이는 문서 전체를 한 번에 읽고 의미적으로 조정한 결과가 아니므로 뒤 구간의 더 적합한 후보나 구간 간 모순을 놓칠 수 있다. 다중 요청의 비용·시간과 중간 실패/중단을 표시하고, 미완료 결과를 정본에 자동 반영하지 않는다. 구간별 후보의 비교·통합 품질 평가는 후속 과제다.

이 제안 기능의 진입 버튼은 접힌 `연구 기준` 제목 바로 오른쪽에 항상 보인다. 제목과 본문을 입력하기 전에는 비활성화 이유를 표시한다. 버튼을 누르면 기준 입력란이 열리고, 전송 범위 확인·AI 실행·항목별 체크·입력란 반영·문서 저장 순으로 진행한다. 버튼 클릭이나 AI 응답만으로 제공사 전송 승인 또는 정본 저장을 건너뛰지 않는다. 이 표시 흐름은 제안 검증·RAG 선택 범위 규칙을 변경하지 않는다.

정본 문서 삭제는 좌측 연구노트 목록에서 대상별로 시작하고, 삭제 범위·영향을 앱 내부 확인창에 표시한다. 미저장 중인 현재 문서나 응답 생성 중에는 차단한다. 문서 자체의 버전·문단·로컬 검토/회차·승인 관계를 한 트랜잭션에서 정리한다. 과거 ContextBundle 답변, 정본 버전에서 만든 레퍼런스, 별도 채택 외부 주장, 다른 기록의 고정 참조가 남아 있으면 원문 계보를 보존하기 위해 거부한다. 삭제 시 근거 자료 자체나 다른 문서/프로젝트 기록을 연쇄 삭제하지 않는다. 마지막 문서인 프로젝트는 함께 제거하고, 공유 프로젝트의 대표 문서를 지울 때는 남은 문서로 대표를 변경한다. 이전 백업은 그대로 남는다.

세션 삭제는 저장 성공 후 UI에 반영하며 메시지 전용 legacy 출처 연결을 같은 로컬 트랜잭션에서 정리한다. Wiki가 공유한 출처 원문은 보존하고 메시지 연결만 해제한다. 이는 레퍼런스 원문/현재 정본의 자동 삭제가 아니며, 남은 RAG 근거의 의미적 지지나 정합성 판정과 무관하다. 문서·레퍼런스 삭제 정책은 별도 수용 기준으로 남는다.

사용 이력이 없는 레퍼런스만 사용자가 직접 확인해 삭제한다. 삭제 직전 한 트랜잭션에서 과거 답변/검토·캠페인·승인 관계·프로젝트 허용 정책·임베딩·외부 Claim의 고정 ID를 검사하고, 참조가 있으면 원문/구간/PDF 원본을 보존한다. 미사용 자료는 구간과 PDF 원본까지 원자적으로 정리한다. 이는 기록의 물리적 삭제이지 이론 주장의 철회가 아니다. 보수적 ID 검사이므로 우연히 같은 문자열이 기록된 경우 삭제가 거부될 수 있고, 대용량 작업공간의 전체 이력 검사 비용·동시 외부 작업 정책은 추가 검증 대상이다.

추출에 실패하거나 텍스트가 없어 검색 자료가 생성되지 않은 PDF 원본도 사용자가 별도 확인 후 삭제할 수 있다. 저장된 원본 hash/바이트를 확인하고, 처리 중·검색 자료/구간 연결·과거 고정 이력이 있으면 삭제하지 않는다. 이 정리는 OCR 실행이나 OCR 계획을 뜻하지 않는다. 삭제한 원본은 현재 작업공간에서 다시 열 수 없으며 이전 JSON 백업이 있다면 그 백업에는 남는다.

대화 목록의 세션 선택을 키보드 접근 가능한 버튼으로 제공하고 현재 선택 상태를 표시한다. 이는 RAG 검색·출처·정합성 판정 계약을 변경하지 않는다. 전체 연구 작업공간의 키보드·좁은 화면 접근성은 별도 검증 대상이다.

대화 헤더의 모델·제목과 설정 대화상자, 질문 전송/중지에도 접근 가능한 이름과 키보드/포커스 경로를 보강했다. 모델 변경은 여전히 사용자의 명시적 선택이며 기존 RAG 미리보기·전송 승인 조건을 우회하지 않는다. 별도 연구 작업공간 모달의 포커스와 모바일 화면은 후속 검증 대상이다.

좁은 대화 화면에서는 사이드바를 기본적으로 감추고 명시적 메뉴로 연다. 닫힌 메뉴는 키보드 순서에 나타나지 않으며, 열린 메뉴의 상태·포커스 순환·닫기 복귀를 검증한다. 이전에 진행한 320px 레퍼런스/정본 화면의 회귀 수정은 유지한다. 이는 대화/자료/정본 선택과 RAG 전송 승인 정책을 변경하지 않는다. 모바일 반응형 추가 작업은 사용자 지시로 보류한다.

## 1. 설계 결정

현재 R4는 [OpenAI 공식 임베딩 계약](https://developers.openai.com/api/docs/guides/embeddings)을 확인한 `text-embedding-3-small`/512차원 초판이다. 원문/질문을 별도로 미리보고 승인한다. 선택 원문 구간 텍스트와 질문만 해당 요청에 보내고 PDF 원본·기준·대화는 임베딩하지 않는다. 색인 세대와 원문/구간/벡터 hash가 같은 구간은 재사용한다. 제공사 내부 revision은 미확인이며 같은 로컬 세대에서도 내부 모델 불변을 보증하지 않는다. 새 세대는 명시적으로 만들고 이전 데이터는 보존한다.

색인은 기본 3/최대 100회·작업 120초, 배치당 16구간/48 KB·구간당 UTF-8 7,500 bytes로 제한한다. 미색인 구간의 위치와 텍스트 없는 PDF 페이지를 표시하며 자동 재전송하지 않는다. 배치 체크포인트를 저장하고 다음 승인에서 캐시를 제외해 재개한다. Worker 정확 코사인과 BM25의 각 최대 20후보를 RRF(k=60)로 합쳐 12개를 제시한다. ContextBundle v1의 호환 확장 `hybrid-rrf-v1`/hybrid trace는 세대/모델/차원 및 색인·미색인 ID, 검색 당시 완성 manifest hash/전환 번호를 보존한다. 백업 v8에서 cache/manifest/원문 참조를 검증하며 답변 근거와 Markdown에도 trace를 표시한다.

Dexie v8에서 작업공간 활성 포인터와 완성 manifest를 분리했다. 작성 중인 새 세대는 기존 검색에 영향을 주지 않고, 선택 자료의 전체 추출 구간과 원문 위치·벡터/hash 검증 뒤 별도 로컬 미리보기/승인으로 원자적으로 활성화한다. 이후 세대는 읽기 전용이며 이전 세대를 선택해 다시 활성화할 수 있다. 질문은 활성 manifest 범위 안의 이번 선택 자료만 검색하고 전송 전후 전환 번호/원문 출처를 다시 확인한다. 부분 색인은 캐시로 보존하지만 새 의미 검색에는 사용하지 않는다. 기존 v7 캐시도 자동 활성화하지 않는다. 텍스트 없는 PDF 페이지는 계속 검색 제외이며, 활성 상태는 검색 준비 상태이지 이론 정합성 판정이 아니다.

잔여: 모의 벡터 결과는 실제 문헌/교차언어 검색 품질 증거가 아니다. 재정렬·모델 변경·모델별 tokenizer/비용 원장·Float32/대용량 성능은 남았다. 질문 전후 전체 manifest 검증의 지연/메모리도 평가해야 한다. 2026-10-03 제공 키로 Node 직접 호출한 합성 입력의 OpenAI Responses/512차원 임베딩은 통과했지만 브라우저 CORS·실제 문헌 검색 품질·독립 사람 레이블은 미검증이다.

Qaxiom은 **버전이 있는 이론 문서를 중심으로 원문 검색, 의미 검색, 주장 의존성 추적을 결합**한다. 사용자가 작성하는 이론과 첨부한 레퍼런스를 구분하고, 검색 결과를 근거로 검토 Issue와 수정 Patch를 생성한다.

| 계층 | 책임 | 판정하지 않는 것 |
| --- | --- | --- |
| 정본 문서·레퍼런스 원문 | 실제 텍스트, 수식, 버전과 출처 보존 | 문서에 적힌 주장이 참인지 |
| BM25 + 벡터 검색 | 관련 용어·표현·문단 후보 발견 | 유사한 두 주장이 양립하는지 |
| 이론·레퍼런스 그래프 | 정의, 가정, 주장, 근거와 영향 범위 추적 | 그래프에 없는 관계가 존재하지 않는지 |
| 정합성 검토 | 조건·추론·수식·인용 검사와 반례 후보 제시 | 일반적인 이론의 절대적 진리 보장 |
| Research Wiki | 개념과 검토 상태를 사람이 탐색하는 화면 | 독립된 외부 증거 제공 |

벡터 검색을 목표 구조에 포함한다. 첫 구현은 BM25를 평가 기준선으로 만들고, 임베딩은 같은 평가 세트에서 효과를 확인하며 추가한다. 벡터를 IndexedDB에 저장하고 Web Worker에서 검색하는 방식으로 시작한다. 전용 벡터 서버와 그래프 서버는 초기 필수 의존성으로 두지 않는다.

## 2. 핵심 사용자 흐름

1. 사용자가 아이디어, 연구 목적, 허용할 가정과 레퍼런스를 입력한다.
2. LLM이 정의·가정·추측을 명시한 초안과 검토할 사항을 제안한다.
3. 사용자가 채택한 초안을 정본 문서의 새 버전으로 저장한다.
4. 해당 버전에서 블록, 기호, Claim과 의존성을 추출하고 추출 불확실성을 표시한다.
5. 내부 정합성과 외부 레퍼런스 호환성을 각각 검사한다.
6. Issue별로 관련 원문, 누락된 전제, 반례 후보와 수정 diff를 제시한다.
7. 사용자가 Patch를 적용하면 새 버전을 만들고 변경 영향 범위를 재검사한다.
8. 전체 검토 범위와 미해결 항목을 확인한 뒤 사용자가 이번 검토를 종료한다.

검토의 산출물은 문서 버전, Issue 목록, 검사 기록, 변경 diff다. 대화는 이 작업을 지시하고 설명하는 인터페이스이며, 대화 요약만으로 정본을 대체하지 않는다.

## 3. 두 종류의 문서와 재첨부 처리

### 작성 중인 이론

- 논리 문서 ID와 불변 버전 ID를 구분한다. 현재 버전은 포인터로 선택한다.
- 문서 변경은 이전 버전을 덮어쓰지 않고 부모 버전을 가진 새 버전으로 저장한다.
- 블록의 논리 ID와 블록 revision/hash를 함께 기록한다. 분할·병합은 이전 블록과의 대응을 보존한다.
- 이론의 목적, 핵심 정의·가정, 기호표, 적용 범위와 미해결 문제를 버전별 `ResearchContract`로 관리한다.

### 첨부 레퍼런스

- 외부 문헌, 사용자 메모, 자체 생성 문서의 스냅샷을 구분한다.
- 원본 파일 hash, 텍스트 hash, 출처 정보와 추출기 버전을 보존한다.
- 자체 문서와 같은 파일/hash 또는 내보내기 manifest가 있으면 동일 계보로 연결한다.
- manifest 없는 수정본은 사용자에게 문서 계보 후보를 제시한다. 의미 유사도만으로 동일 문서라고 확정하지 않는다.
- 예전 자체 문서는 변경 비교에 사용한다. 자기 주장을 독립된 외부 증거로 재인용하지 않는다.
- 기본 검색은 선택한 정본 버전과 선택한 레퍼런스 버전으로 제한한다. 과거 버전 검색은 비교 작업에서 명시적으로 활성화한다.

외부 문헌도 참의 보증이 아니다. 그 문헌이 무엇을 어떤 조건에서 주장하는지 기록하며, 실험 결과·저자 주장·증명을 구분한다.

## 4. 데이터 계약

다음 표는 신규 또는 확장할 데이터 계약이다. 실제 필드는 구현 단계에서 런타임 스키마로 고정한다.

| 객체 | 핵심 필드 및 규칙 |
| --- | --- |
| ResearchProject | 연구 목적, 정본 문서 ID, 허용 레퍼런스 집합, 검색·전송 설정 |
| Document / DocumentVersion | 문서 계보, 역할, 부모 버전, 원문 hash, 생성 시각; 버전 내용 불변 |
| DocumentBlock | 문서 버전, 논리 블록 ID, revision/hash, 순서, 섹션 경로, 원문, 블록 종류 |
| SourceSpan | 문서 버전·블록 revision, 문자 범위, 원문 발췌/hash; PDF는 페이지·가능한 좌표, Markdown은 블록·줄 위치 |
| ResearchContract | 버전별 목적·핵심 전제·정의·기호·범위와 해당 원문 블록 참조 |
| Symbol / Definition | 기호, 의미, 정의된 scope, 차원·단위(해당 시), 원문 참조 |
| Claim | statement, 종류, 전제, 양화·적용 범위, 문서 버전, SourceSpan, 생성 출처 |
| ClaimRelation | 양끝 Claim revision, 관계, 근거·추출기, 검토 상태 |
| WikiPage | Claim과 원문 참조에서 만든 개념별 뷰; 자체 독립 근거로 승격 금지 |
| IndexGeneration / Embedding | 원문 hash, 전처리·청크 버전, 모델 ID/revision, 차원, 거리 함수, 생성 상태 |
| RetrievalRun | 질의·필터, 정본 버전, 인덱스 세대, 후보·순위·선택 이유, 실제 전달한 근거 ID |
| CheckRun / CheckResult | 검사 종류·도구/모델 버전, 검사 대상 revision, 실행 결과, 범위·누락·실패 기록 |
| ConsistencyIssue | 종류·심각도·상태, 영향 Claim, 원문 근거, 설명, 반례 후보와 해결 조건 |
| TheoryPatch | baseVersion, 변경 전 블록 hash, 수정 작업, 도입·변경 가정, 해결 후보 Issue, 영향 범위 |

Claim의 종류(`assumption`, `definition`, `conjecture`, `lemma`, `theorem`, `result`)와 사용자 검토 상태(`proposed`, `accepted`, `rejected`)를 분리한다. 사용자 채택은 증명이 아니다. 수치·심볼릭·형식 증명 결과는 별도 CheckResult로 기록하고 Claim에 단일 `verified` 플래그를 붙이지 않는다.

관계는 `depends_on`, `uses_definition`, `supports`, `contradicts_candidate`, `refines` 등을 사용한다. 자동 추출 관계에는 근거와 불확실성을 남긴다. 관련성이 높다는 이유만으로 `supports`를 부여하지 않는다.

## 5. 문서 수집과 색인

### 수집

- 먼저 Markdown/텍스트 정본을 지원해 실제 이론 작성 루프를 완성한다.
- PDF는 Worker에서 추출하고 읽기 순서·다단·표·수식·각주 품질을 기록한다.
- 스캔·암호화·손상 문서는 명시적인 처리 상태를 반환한다. OCR은 비목표이며, 텍스트 계층이 없는 문서는 검색 가능한 텍스트 또는 PDF를 사용하도록 안내한다. 부정확한 수식 추출을 검사 성공으로 간주하지 않는다.
- PDF 원본 바이트와 추출 텍스트를 보존해 페이지 재열기와 추출 재검증을 지원한다. legacy `documents`와 별개로 `pdf_assets`에 원본 ArrayBuffer·파일 hash·페이지 체크포인트를 저장한다.

### 분할

- 문서 블록은 정본 단위, 검색 청크는 재생성 가능한 파생 단위로 구분한다.
- 제목·정의·정리·증명·수식과 설명의 경계를 우선한다. 긴 블록만 추가 분할한다.
- 초기 실험값은 청크 400~800 토큰, 필요한 경우 약 10% 중첩이다. 고정 정답으로 취급하지 않는다.
- 자식 청크를 찾으면 부모 섹션과 필요한 인접 블록을 회수한다. 페이지 경계를 넘으면 복수 SourceSpan을 보존한다.
- 검색용 문맥에는 문서명·섹션·기호를 우선 사용한다. LLM 문맥 설명은 별도 파생 필드로 저장하며 원문 인용에 섞지 않는다.

### 인덱스

- BM25: 한글·영문 혼용, 약어·별칭, 기호와 정리 번호를 평가한다. 수식의 원형도 보존한다.
- 벡터: 원문 청크부터 임베딩한다. Claim 임베딩은 후속 단계로 추가하고 검색 출처를 구분한다.
- 임베딩 모델/revision·차원·전처리가 다른 벡터는 서로 비교하지 않는다. 질의도 같은 설정으로 임베딩한다.
- 그래프: 이론의 가정·정의·추론 의존성을 먼저 만들고 자주 참조하는 외부 주장으로 확장한다. 모든 레퍼런스의 전면 그래프화는 첫 색인의 필수 조건이 아니다.
- 임베딩 미준비·실패 상태에서도 BM25와 정확 참조는 동작하며 현재 검색 범위를 표시한다.

## 6. 검색과 컨텍스트 구성

### 작업별 경로

| 작업 | 반드시 포함할 내용 | 검색으로 보충할 내용 |
| --- | --- | --- |
| 이론 전개 | ResearchContract, 대상 블록, 적용 정의·전제 | 관련 외부 결과와 한계 |
| 내부 정합성 | 대상 Claim, 의존 전제·정의, 영향받는 후속 Claim | 다른 섹션의 동일 용어·충돌 후보 |
| 외부 호환성 | 자체 주장과 조건, 선택한 외부 문헌 범위 | 지지·반대·적용 범위가 다른 원문 |
| 수정 영향 | 변경 블록, 승인된 의존성의 영향 집합 | 추출 누락을 찾는 용어·기호 검색 |
| 문헌 종합 | 포함·제외 문서 목록, 주제별 검토 범위 | 문서별 대표 원문과 상충 결과 |

정확한 ID로 지정한 정의·필수 전제는 top-k 검색 경쟁에서 탈락시키지 않는다. 초기 후보값은 BM25 30개, 벡터 30개, 그래프 이웃 1-hop이다. 합집합을 RRF로 결합하고 원문 중복 제거, 문서 다양성, 조건 일치, 원문 재정렬을 적용한다. 2-hop은 근거가 부족한 경우에만 제한적으로 확대한다.

최종 컨텍스트 크기는 고정 청크 수가 아니라 모델 한도에서 시스템 지시, 출력 예산, 대화, 필수 전제를 뺀 값으로 결정한다. 필수 내용이 넘치면 검토를 세부 작업으로 나누고 생략 범위를 기록한다. 핵심 전제를 몰래 잘라내지 않는다.

검색 예산과 검토 범위는 구분한다. top-k 검색만으로 문서 전체가 정합하다고 판정하지 않는다. 전체 검토는 Claim 목록을 순회하고, 미추출 블록도 별도로 점검한 후 검사율을 기록한다. 그래프 밖 모순 가능성도 남긴다.

LLM 요청에는 아래 내용을 버전이 고정된 ContextBundle로 전달한다.

- 작업과 ResearchContract의 원문 참조
- 대상 블록·Claim 및 의존 전제
- 선택된 레퍼런스 원문과 인용 ID
- 현재 Issue와 필요한 이전 검토 결과
- 검토하지 못한 범위와 답변 형식

사용자는 전송할 문서·구간을 펼쳐볼 수 있다. 회수한 문서 텍스트는 인용 데이터로 구분하고 문서 안의 지시가 도구 실행이나 시스템 지시를 바꾸지 못하게 한다.

## 7. 정합성 검토 설계

### A. 구조·기호 검사

결정적으로 검사할 수 있는 항목부터 구현한다: 끊어진 ID·인용, 오래된 버전 참조, 선언된 기호의 scope 충돌, 누락된 의존 노드, 선언된 증명 의존성의 순환, 알려진 단위 규칙 위반.

현재 `local-v2`는 버전 고정 정본의 `qaxiom-declarations` fenced JSON에서 symbols(name/meaning/definedAt/scope), uses(name/at), dependencies(from/to/kind)를 읽는다. 사용자 명시 선언만 대상으로 NFKC 기호 이름과 literal 의미 문자열/범위 충돌, 미정의·범위 밖 사용, 현재 버전에 없는 블록 ID, proof 의존성의 순환을 검사한다. concept 순환은 허용하며 선언하지 않은 관계를 추론하지 않는다. 빈 scope는 문서 전체다. 원문 JSON 블록이 Issue의 정확한 인용 근거이며 자연어 의미·단위·증명의 완전성을 보증하지 않는다. 새 테이블이 아닌 정본 버전/원문 블록으로 보존한다.

닫히지 않은 fence·잘못된 JSON/필드, 선언 JSON 100,000자·문서 전체 항목별 1,000개·기호 범위 비교 100,000단계 초과는 invalid_declaration Issue로 남긴다. 긴 증명 사슬은 반복형 DFS로 검사한다. `local-v1`의 기존 결과/백업도 유지하고 `local-v2`가 그 검사 범위를 포함하므로 후속 전체 범위 통과 시 사용자 해결 확인에 사용할 수 있다. 반대 방향이나 로컬/LLM 검사 간 해결 승격은 허용하지 않는다.

자연어 정의의 충돌, 숨은 가정, 정의 추출 완전성은 결정적 검사를 보장할 수 없으므로 의미 검토 후보로 표시한다. 개념 링크 그래프의 순환 자체는 오류가 아니다.

### B. 주장과 논증 검토

LLM 검토는 Claim, 전제, 원문 구간을 입력받아 다음을 구조화해서 반환한다.

- 누락 전제, 범위·양화 변화, 필요/충분조건 혼동, 순환 논증 후보
- 충돌하는 두 구간과 충돌이 성립하는 공통 조건
- 반례 후보, 판단 불충분, 추가 검증 필요
- Issue별 원문 인용과 수정 방향

인용 ID 존재·버전·범위 일치는 코드로 검사한다. 인용이 주장을 실제로 지지하는지는 별도 의미 검토와 사람 평가가 필요하다. 검토 모델의 자신감은 확률적 보증으로 표시하지 않는다.

### C. 수학·실험 검사

- 적용 가능한 식에는 차원 분석, 심볼릭 동치, 경계값·수치·property-based 검사를 연결한다.
- 수치 성공은 일반 증명이 아니다. 반례가 나오면 입력, seed, 가정 충족 여부를 저장한다.
- Lean 등의 형식 검증은 형식화한 명제와 명시된 공리 범위에 한해 기록한다. 별도 실행 환경이 필요한 단계는 브라우저 MVP 뒤에 둔다.
- 생성된 코드를 브라우저 본문에서 임의 실행하지 않는다. 허용된 검사기와 격리된 실행 계약을 사용한다.

### D. 외부 레퍼런스 호환성

내부 논리 검사와 별도 결과로 표시한다. 외부 결과와 다르다는 이유만으로 내부 모순이라고 판정하지 않는다. 가정, 정의, 단위, 적용 범위와 경험적 결과를 비교해 `compatible`, `conflict_candidate`, `different_scope`, `insufficient_evidence`로 보고한다.

자체 문서의 이전 버전은 외부 근거 점수에 포함하지 않는다. 생성 검토와 다른 컨텍스트의 비판 검토를 추가할 수 있지만, 여러 모델의 합의만으로 참이나 증명을 선언하지 않는다.

## 8. Issue → Patch → 재검사

1. CheckRun은 검사 대상 정본 버전과 레퍼런스 버전을 고정한다.
2. Issue는 근거·범위·해결 조건을 갖는다. 근거 없는 지적은 검토 의견으로 구분한다.
3. Patch에 변경 전 hash, 새 가정, 영향 Claim, 해결하려는 Issue를 포함한다.
4. 사용자에게 diff와 영향 범위를 보여주고 승인하면 새 버전을 원자적으로 저장한다.
5. baseVersion/hash가 달라졌으면 Patch 적용을 중단하고 현재 버전 기준으로 다시 생성한다.
6. 변경 블록의 색인과 파생 Claim을 갱신하고 영향받은 CheckResult를 `stale`로 표시한다.
7. 재검사 성공 후 Issue를 닫는다. 생성 모델의 “수정 완료” 주장만으로 닫지 않는다.

사용자가 반복 실행을 시작할 때 회차·토큰/비용·시간 예산을 정한다. 초기 제안은 최대 3회 검토·수정 제안이다. 자동 초안 수정은 작업 브랜치에서만 수행하고 정본 반영은 승인한다.

중대 문제 발견, 예산 소진, 같은 Issue 반복, 이전 내용으로 되돌아가는 진동, 외부 도구 실패, 근거 부족 시 반복을 멈추고 원인을 표시한다. 사용자는 언제든 중단·재개할 수 있다.

현재 캠페인은 중대 Issue·실패/중단·선택 블록 미검사/limitations/근거 부족 Issue·구조적 반복/과거 해결 재발 후보를 추가 요청 예약 시 검사한다. 반복 후보는 종류와 블록 ID/정규화 원문 인용의 일치이며 설명의 바꿔쓰기는 무시한다. 문맥·범위 변경에 따른 오탐 및 다른 표현/블록 재분할로 인한 누락이 가능하므로 의미적 재발 판정은 아니다. 분할 요청 밖의 미검사 구간만으로 매번 중단하지 않는다. 사용자가 확인 사유를 기록하면 해당 run의 원인만 수동 재개 허용하며 미해결 Issue·검사 범위·사용 예산을 바꾸지 않는다. 종료는 버전과 사유를 남기며 통과로 승격하지 않는다. 명시적 새 검토에서 예산을 새로 시작하되 이전 캠페인은 보존한다. 확인/종료는 백업 v6 호환 필드로 저장하고 참조 검증 후 복원한다.

검토 상태는 `진행 중`, `수정 필요`, `설정된 검사 범위 통과`, `판단 불충분`, `중단`으로 표시한다. 통과 보고서에는 Claim/블록 검사 범위, 미검증 항목, 외부 자료 범위, 검사기 버전을 포함한다. “이론이 완전히 정합해졌다”는 보증으로 표현하지 않는다.

## 9. 로컬 구현 및 저장 일관성

- Dexie는 정본·근거·검토 기록의 영속 저장소다. Worker가 색인 생성과 벡터 연산을 담당한다.
- 처음에는 Float32 벡터의 정확 코사인 검색을 측정한다. 10,000 × 768차원 × 4byte는 벡터만 약 30.7 MB이며 텍스트·인덱스·Worker 복사 메모리는 별도다.
- 측정한 검색 지연·메모리 목표를 넘으면 ANN을 도입하고 정확 검색 대비 Recall 손실을 검사한다. 전문 DB 도입은 로컬 방식의 한계나 다중 기기 요구가 확인된 뒤 결정한다.
- 원격 임베딩·Claim 추출·재정렬은 각각 전송 범위와 비용이 있는 작업으로 표시한다. 로컬 검색이 가능하다는 사실이 원격 전송 없음을 뜻하지 않는다.
- 새 인덱스는 임시 세대에서 생성하고 완성 후 활성 포인터를 교체한다. 중단 시 완료된 작업부터 재개한다.
- 인덱스가 정본보다 오래됐으면 현재 버전 필수 블록을 직접 읽고 stale 상태를 알린다. 미색인 버전을 예전 자료로 조용히 대체하지 않는다.
- 삭제된 원문·Claim은 현재 검색에서 제외하고 파생 관계·인용을 무효화한다. 역사 버전의 보존과 영구 삭제는 별도 동작으로 설계한다.
- 저장·복원·색인·검토가 충돌하지 않도록 프로젝트별 쓰기 직렬화와 버전 비교를 둔다. 한 요청은 한 스냅샷에서 읽는다.

R3 초판의 v5 `review_runs`에 이어 Dexie/백업 v6에서 문서별 `review_campaigns`를 추가했다. 검토 run 안에 Claim 후보·채택 상태, 인용 근거와 해결 조건을 가진 Issue, 변경 전 hash/새 가정/적용 버전의 Patch를 저장한다. 백업은 v1–v5를 계속 읽으며 검토 계보와 캠페인의 버전·모델·소유권·블록 범위·예산 참조가 틀리면 교체 전에 거부한다. 모델 검토 입력·UI/보고서 경로도 연결되어 있다.

캠페인은 기본 3/최대 100회와 회차×120초 시간 예산을 영속 저장한다. 전송 전 원자적으로 실행을 예약해 다른 탭의 중복 실행을 차단하며 실패·중단도 회차에 포함한다. 저장된 분할 계획은 버전과 블록에 고정되고 전체 연구 기준을 매 요청에 포함한다. 완료 응답의 실제 검사 블록만 진행 범위에 합산한다. 다음 구간마다 사용자가 선택·미리보기·승인하며 자동 호출하지 않는다. 복원은 진행 요청 소유권을 종료하고 미검사/결과·비용 미확인으로 남긴다. 단일 블록/필수 기준이 40 KB를 넘으면 명시적으로 작업 분리를 안내한다. 누락 ID 64개 초과는 연속 위치 범위로 전송하고 로컬 run에는 전체 미검사 ID를 보존한다. 분할 구간의 처리 완료는 문서 전체의 상호 논증 검토/정합성 통과가 아니다.

기존 `WikiPage`와 `SourceSpanRecord`는 최소 타입을 유지하며 새 Research Wiki는 정본 Claim·승인 관계·원문의 파생 뷰다. `ReferenceDocument`/`ReferenceSpan`은 불변 ID/hash와 문자·행/페이지로 원문을 고정하며 legacy 출처를 재해석하지 않는다. ContextBundle v1의 문맥/기준 `assembly` 확장에 이어 R4의 검색 방법/세대/색인 범위와 선택적 manifest hash/전환 번호를 호환 확장했다. 현재 Dexie/백업 v19이며 assembly/manifest trace 없는 과거 묶음과 v1–v18 백업을 계속 복원한다. 기준·부모/누락 구간을 정본/원문에 대조하고 hybrid trace의 세대/색인 범위/manifest와 승인 관계·그래프 계획·수정 영향·독립 원문 대조·별도 관계 승인 계보 참조/hash를 확인한다. 실제 문헌 품질·모델별 예산은 남아 있어 R2/R4 전체 수용 기준 완료가 아니다.

R5 초판의 `research_relations`는 현재 정본 버전의 채택 Claim(run/claim/version/block hash·원문) → 같은 버전의 채택 Claim 또는 선택 레퍼런스 SourceSpan(source/span hash·원문)를 저장한다. 관계와 사유를 미리보고 사용자가 승인하며, 같은 관계의 동시/중복 게시를 차단한다. 문서별 1,000/작업공간 10,000관계, 조건/사유별 2,000자 한도를 둔다. 승인·철회 이력과 hash를 보존하고 버전 변경·주장 채택 철회는 현재 그래프에서 제외한다. 현재 활성 관계만 역참조·의존 전제·수정 영향과 명시 증명 의존성의 순환 후보에 반영한다. concept 순환은 허용하며 다른 검토 회차의 동일 의미 주장이나 미선언 관계를 자동 합치지 않는다.

Wiki는 과거/현재 Claim과 고정 원문 블록·레퍼런스 페이지를 탐색하고 Markdown으로 내보낸다. 원문 연결의 compatible/conflict_candidate/different_scope/insufficient_evidence와 양쪽 가정·정의·범위는 사용자 대조 기록이다. 메모/자체 문서와 어느 정본과든 같은 hash의 자료는 독립 외부 대조에서 제외한다. 새 모델 API나 자동 의미 판단은 없다. 그래프 후보·필수 전제를 ContextBundle에 회수하는 경로, Patch 영향 검토, 독립 외부 Claim·개념 통합과 승인형 LLM 대조/사람 평가는 아직 연결하지 않았다. 이 초판을 목표 하이브리드 RAG 전체 완료로 판정하지 않는다.

### 승인 그래프를 이용한 내부 논증 검토 (v10)

사용자가 별도 체크박스를 선택하면 선택 목표 Claim의 활성 depends_on/defines 경로에서 추가 정본 블록을 회수한다. 이 범위 안의 승인 Claim 관계만 `ReviewGraphContext`로 고정한다. 목표/추가 전제 ID, 원문·관계 hash, proof 순환 후보, stale/철회/미채택/범위 밖/외부 미전송 수와 문맥 hash를 미리보기·ReviewRun·회차·Markdown·백업에 보존한다. 로컬 비교용 전체 상태 서명은 제공사에 보내지 않고 불투명 SHA-256만 기록한다. 외부 관계의 발췌/파일명/사유는 이 경로에 넣지 않는다.

문맥 전체를 기존 40 KB 검토 예산에 포함하며 초과하면 거부한다. 예약 직전과 게시 시점에 원문·관계·주장 채택 상태를 다시 확인한다. 전송 전 변경은 회차를 사용하지 않고 거부하며 전송 후 변경은 실패/검사 0으로 저장한다. 실제 제공사 비용은 미확인이다. 알려진 proof 순환이 있으면 모델의 무문제 보고만으로 범위 통과를 저장하지 않는다. 추가 전제 첨부와 실제 checkedBlockIds를 구분한다.

현재 Dexie/백업은 v10이고 v1–v9를 복원한다. graph 범위·고정 승인 관계/원문 계보·문맥/hash 검증을 마친 뒤 원자적으로 교체한다. 실행 중 요청은 중단 기록으로 복원하며 자동 재전송하지 않는다. 이후 관계 철회·Claim 채택 변경은 과거 검토 문맥을 지우지 않는다.

제한: 이 기능은 내부 검토에만 연결했다. 답변 ContextBundle 그래프 후보/전제, 그래프 예산 기반 분할, Patch 영향 재검사, 외부 Claim/선택 원문 LLM 대조와 실제 사람 평가는 남았다. 첨부·사용자 승인·hash/순환 검사는 정합성 증명이 아니다.

### 선택 정본 그래프를 답변 ContextBundle에 회수 (v11)

레퍼런스 검색의 연구 기준에서 사용자가 별도 그래프 포함 옵션과 목표 블록을 선택한다. 활성 depends_on/defines 전이 폐쇄의 추가 정본 블록과 그 범위의 승인 Claim 관계를 `ContextBundle.graph = {context, blocks}`로 고정한다. 현재 문서 전체·미선택 외부 관계를 자동 첨부하지 않는다. 원문과 관계/hash/순환 후보·제외 수는 전송 미리보기에서 확인하고 최종 질문 승인 후에만 제공사로 전달한다. 기본 비활성이다.

정본 블록은 [[G1]] 인용으로 기존 [[R1]] 레퍼런스와 분리한다. 답변/Markdown은 전송 당시 버전/hash·목표/추가 전제·관계와 전체 블록을 보존한다. 유효 ID 연결은 의미적 지지나 실제 논증 검사 완료가 아니다. graph의 사유/인용은 신뢰하지 않는 데이터로 전달하며 시스템 지시로 승격하지 않는다.

12,000 UTF-16 예산은 ResearchContract/graph 전체와 선택 근거를 우선 예약하고 나머지에 원문 부모 문맥을 확장한다. 추가 전제를 자르지 않고 초과하면 거부한다. 부모 문맥 누락은 모두 위치와 사유를 남긴다. 대화/질문/메타데이터/그래프 지시를 포함한 48 KB 요청 한도는 추가로 검사한다. 모델 tokenizer/비용 보장은 아니다.

UI 승인과 API 호출 직전, 스트림 완료 전에 정본/승인 관계/주장 채택 및 선택 원문 출처/hash를 다시 확인한다. stale 미리보기는 API 0으로 거부하고 전송 후 변경은 완료 답변으로 승격하지 않는다. 제공사 오류·비용과 생성 내용의 학술 품질은 미확인이다. 승인 모델의 키가 없는 RAG 요청/재시도는 자동 제공사 전환하지 않는다.

Dexie/백업 v11은 기존 v1–v10을 유지한다. graph 범위·고정 정본 원문/관계 계보·문맥/hash 검증 후 전체를 원자적으로 복원하며 실패 시 기존 데이터 보존. 과거 답변의 graph는 이후 철회/버전 변경과 구분해 보존한다. 과거 답변으로 자동 재전송하지 않는다.

안전 설계 참고: [OpenAI 공식 안전 지침](https://developers.openai.com/api/docs/guides/safety-best-practices)의 입력 제한·사람 검토·원문 확인·한계 고지 원칙을 참고했다. 이 구현이 프롬프트 주입을 완전히 막는다고 주장하지 않는다. 실제 유효 키 호출/모델 품질과 보안 red-team 평가는 별도 수용 과제다.

잔여: 현재 목표 수동 선택/레퍼런스 근거 동반 답변이다. 그래프 후보 검색·정본 단독 질문·그래프 고려 분할·Patch 영향/외부 Claim 대조·프로젝트 통합은 남았다. 이 연결을 R5 전체나 서비스 전체 완성으로 판정하지 않는다.

### 정본만으로 질문하는 문맥 (v12)

같은 레퍼런스/정본 문맥 흐름 안에 `정본만으로 질문 미리보기`를 추가한다. 레퍼런스 등록·검색 없이 정본 기준과 목표 블록을 선택하고 승인 의존/정의 경로의 추가 전제를 미리본 뒤 질문한다. 등록하거나 선택한 외부 자료가 있어도 이 첨부에는 포함하지 않는다. 기존 대화는 함께 전송하므로 원문 없는 독립 질문은 새 대화에서 시작하도록 안내한다.

`ContextBundle.retriever = graph-canonical-v1`은 수동 목표/승인 전제 직접 회수이며 BM25/벡터 검색 점수가 아니다. selectedSourceIds/evidence/원문 부모 범위는 비어 있고 graph/정본 ResearchContract는 필수다. 원문 근거 없음과 없는 R 인용을 미리보기·답변·Markdown에서 구분한다. G 인용은 정본 원문 연결만 검증하고 자체 문서를 외부 증거로 승격하지 않는다.

빈 질문/목표, 그래프 없는 정본 단독 기록, 외부 자료/하이브리드 결과 혼합, 위조된 원문·범위·hash는 거부한다. 목표/질문 변경으로 미리보기를 무효화하고 기존 예산·전송 전후 graph 검증을 유지한다. Dexie v1–v11을 유지하고 v12/백업 v12에 새 retrieval 계약을 추가한다. 기존 v1–v11은 계속 가져오며 복원 실패 시 기존 데이터 유지.

다음은 질문 기반 후보 검색/목표 제안·그래프 예산 분할·Patch 영향/외부 대조 검토다. 수동 정본 회수만으로 의미 의존성 완전성, 실제 모델 품질 또는 R5 전체를 완료했다고 판단하지 않는다.

### 질문으로 정본 목표 후보 찾기

정본 그래프 범위 안에서 현재 질문을 Worker BM25로 검색해 최대 12개 목표 후보를 제안한다. 원문 검색과 공통 점수 계산을 사용하지만 입력은 선택 정본의 블록뿐이다. 다른 정본·외부 자료를 조회하거나 제공사에 질문/원문을 보내지 않는다. 후보는 자동 선택하지 않고 사용자의 추가/해제 뒤 최종 미리보기에서 전송을 승인한다.

각 후보는 원문과 용어 점수, 활성 승인 의존/정의 경로의 추가 전제·관계·proof 순환 후보·외부 미전송 수를 표시한다. 정의의 전이와 concept 순환은 방문 집합으로 종료하며 의미 동일성/미선언 관계를 추론하지 않는다. 필수 문맥이 40 KB 한도를 넘으면 연결 범위 미확인/초과로 표시하고 자동으로 전제를 버리지 않는다. 실제 답변 문맥 12,000 UTF-16/48 KB 한도도 최종 미리보기에서 유지한다.

질문 1–2,000자·50,000블록/200만 문자·12개 후보·30초 작업 제한과 수동 중단을 제공한다. 질문/버전 변경은 기존 Worker/비동기 확인을 종료하고 후보를 지운다. 검색 전후 정본/승인 관계/채택의 일치를 확인하고 변경되면 전체 후보를 게시하지 않는다. 없음 결과는 용어 불일치이며 관계 없음/근거 없음/정합성 판정이 아니다.

검색 순위와 점수는 일시적인 로컬 UI 상태이며 현재 요청/백업은 선택된 목표·고정 정본/승인 문맥만 보존한다. 기존 Dexie/백업 v12 계약을 유지한다. 이 초판은 어휘 기반 목표 제안+승인 그래프 문맥 확장이다. 의미 후보·통합 RRF/재정렬·독립 실제 품질 평가·검색 이력·대용량/후보별 검증 비용은 남았다.

### 승인 그래프를 고려한 검토 분할 (v13)

그래프 옵션을 켜고 계획을 저장하면 목표 블록을 원문 순서로 탐욕적으로 나눈다. 각 묶음의 승인 depends_on/defines 전이 전제·관계와 ResearchContract 전체를 포함한 실제 요청 문자열을 UTF-8 40,000 bytes 한도로 검사한다. 목표는 구간 사이에서 겹치지 않지만 공통 필수 전제는 반복된다. 단일 목표조차 넘으면 전제를 생략하지 않고 기존 계획을 유지한다. 무결성/상태 변경은 분할 사유가 아니라 전체 저장 실패다. 계산과 저장 사이의 정본/관계/채택 변경도 트랜잭션 재확인으로 차단한다.

계획은 구간별 ReviewGraphContext를 고정한다. 다음 구간 선택은 저장된 그래프 모드와 미검사 목표를 복원하며 API를 호출하지 않는다. 최종 미리보기/명시 실행은 여전히 필요하고 그래프가 바뀌면 계획을 다시 저장하도록 요구한다. 수동 옵션/블록 변경은 계획 경로가 아닌 새 범위 검토다. 진행률은 같은 그래프 상태의 complete 회차에서 실제 검사된 target에만 적용하고 premise를 다른 구간의 target 검사로 계산하지 않는다. proof 순환 후보도 보존하며 계획 성공/구간 완료로 해결 표시하지 않는다.

Dexie v1–v12 유지 + v13/백업 v13. 기존 v1–v12 가져오기와 populated v12 이전을 유지한다. 계획 구간/전제/범위·40 KB 예산·승인 원문 계보·문맥/관계 hash를 검증하고 복원 실패 시 기존 작업공간을 보존한다. 나중 철회는 과거 계획의 고정 문맥을 삭제하지 않는다. 탐욕적 분할의 최적성·모델별 토큰/비용·구간 간 논증·대용량 성능은 보장하지 않는다. 다음은 Patch 영향 재검사·독립 외부 대조/실제 평가다.

### 수정 영향의 고정과 후속 버전 범위 선택 (v14)

Patch 적용 전, 변경 블록에서 승인된 depends_on/defines 역참조와 supports/contradicts 양끝을 방문 집합으로 추적한다. 같은 블록의 여러 Claim은 보수적으로 함께 후보가 되며 의미 동일성 추론은 아니다. 영향 목표의 전이 전제/정의를 추가하고 새 가정은 ResearchContract 전역 변경이므로 전체 블록을 목표로 잡는다. 외부 관계는 누락 개수만 기록하고 원문/파일명/조건을 첨부하지 않는다. 영향 확인은 제공사 요청이 아니므로 40 KB 한도에 맞춰 전제를 잘라내지 않는다.

사용자는 diff·새 가정·영향 원문을 확인한 뒤 승인한다. 적용 전 ReviewGraphContext와 제안 hash를 저장하고, 그래프/채택/원문·replacement/가정 변경은 승인을 거부한다. 트랜잭션 재확인 후 새 버전과 영향 기록을 함께 저장하며 실패 시 둘 다 롤백한다. 과거 Claim/관계를 새 버전의 활성 승인으로 옮기지 않는다.

적용 후 별도 버튼은 현재 후속 버전의 재검사 범위만 선택한다. 논리 ID/predecessor로 분할·병합을 따라가며 후속 추가/수정 블록도 포함한다. 누락 계보 또는 연구 기준 변경은 전체 범위로 넓힌다. 이전 graph는 입력에 붙이지 않고 현재 원문/전체 기준을 새로 미리보고 승인한다. 큰 범위는 기존 분할 계획/요청 예산을 사용한다. 실제 검사 수는 현재 버전의 같은 종류 complete 회차 checkedBlockIds로 계산하고 부분 범위 완료를 Issue 해결 또는 전체 정합성으로 승격하지 않는다. 기존 전체 범위 재검사 통과·사용자 해결 확인 조건을 유지한다.

Dexie v1–v13 유지 + v14/백업 v14. 영향 범위·고정 승인 원문/계보·그래프/관계 hash·원래 수정 제안 hash를 검증 후 복원한다. 적용 후 관계 철회도 이력을 보존하며 genuine v13 Patch/스키마 이전에 영향 이력을 새로 만들지 않는다. 보고서와 백업에 고정 기록이 남는다. 미선언 영향의 어휘/기호 탐색·의미 계보·구간 간 논증·실제 품질/대용량 검증은 남았다.

### 독립 외부 원문의 승인형 대조 (v15)

사용자가 직접 이론 블록과 독립 external SourceSpan, 양쪽 적용 조건을 1–8쌍 선택한다. 스팬은 명시 선택이며 BM25/벡터 점수의 품질 주장 없이 다룬다. 요청은 전체 ResearchContract·선택 블록/구간·파일명/행/PDF 페이지·누락 범위를 고정한다. 대화·PDF 원본·미선택 파일/원문·기존 버전 계보 ID는 보내지 않는다. 모델/조건/원문/누락을 미리보고 별도 승인한다. 준비/예약/호출 전후의 정본·출처/역할·원문/위치/hash 변경은 전송 또는 결과 승격을 차단한다.

자체 문서/메모·origin 있는 자료·어느 정본 버전과든 같은 hash의 자료는 독립 대조에서 제외한다. 이 검사는 출처 분류 무결성이지 학술적 독립성의 증명이 아니다. 수정 재첨부본의 자기 근거 여부·저자/실험 독립성·PDF 수식/읽기 순서는 사용자 원본 대조와 평가가 필요하다. 텍스트 없는 페이지는 emptyPages로, 미선택 구간은 자료별 위치 범위로 기록한다.

`external-v1` 결과는 실제 대조한 pair ID와 compatible/conflict_candidate/different_scope/insufficient_evidence 후보, 정확한 양쪽 인용·조건·설명으로 검증한다. 환각 인용/미선택 쌍·중복·빈 조건은 거부한다. 내부 checkedBlockIds는 0이며 outcome=insufficient로 내부 논증·전체 정합성 통과와 분리한다. 외부 분류는 자동 관계 승인/문서 수정/Issue 해결이 아니다. 기존 Wiki의 명시 관계 승인 절차와 사람 확인은 별도로 필요하다.

외부 요청도 기존 캠페인 회차/시간 소유권을 공유한다. 기본 3/최대 100회·120초·UTF-8 40,000 bytes/응답 100,000자, 실패/중단 회차·미검사와 제공사 비용 미확인을 보존한다. 다음 검토에는 기존 중단 사유의 수동 확인이 필요하다. 키 없는 선택 모델은 예약 전에 거부하며 제공사를 바꾸지 않는다. 실패/기한 초과·전송 후 변경은 대조 수 0으로 남긴다. 복원은 실행을 stopped로 종료하며 자동 재전송하지 않는다.

Dexie v1–v14 유지 + v15/백업 v15. 출처/원문·전체 기준·누락 범위/인용·문맥 hash·예약 범위/소유권을 검증하고 실패 시 기존 작업공간을 유지한다. 보고서와 백업에 고정 대조 기록을 남기고 결과에서 전체 원문/PDF 확인을 제공한다. genuine v14 이전에 외부 검사를 새로 만들지 않는다.

OpenAI Docs의 [비신뢰 입력과 제한된 출력 흐름](https://developers.openai.com/api/docs/guides/agent-builder-safety), [구조화 출력과 경계 사례](https://developers.openai.com/api/docs/guides/structured-outputs)를 참고해 고정 지시와 선택 사용자 데이터를 구분하고 앱 JSON/원문 검증을 추가했다. 네이티브 Structured Outputs 적용이나 실제 모델 호출 검증을 했다는 의미는 아니다. 의미 조건 검증·실제 학술 품질/사람 평가·외부 Claim/프로젝트 통합·모델별 토큰/비용·대용량은 남았다.

### 미선언 수정 영향의 로컬 어휘 후보

적용된 Patch의 수정 전 원문·replacement와 현재 후속 버전을 검증한 뒤 기존 영향 범위 밖을 검색한다. NFKC 소문자 단어·숫자·한글 bigram을 사용하며 제거/추가/유지 용어의 일치를 구분한다. 유지 기호도 포함해 이름은 같고 식만 달라진 경우의 후보를 놓치지 않도록 한다. 동의어·의미 의존성·LaTeX/연산자 의미·수식 동치를 해석하지 않는다. 제거/추가 일치 수에 2배, 유지 일치 수에 1배 가중치를 주고 문서 순서로 동점을 정리한다. 검색 결과가 없어도 영향 없음을 증명하지 않는다.

임시 Worker 검색은 50,000블록·총 2,000,000 UTF-16 문자·수정 전후 합계 2,000,000자·용어 1,000개·30초 한도, 명시적 취소를 지원한다. 한도 초과는 조용히 원문/용어를 자르지 않고 거부한다. 후보 최대 24개와 미표시 일치 개수를 알린다. 외부 자료나 API는 사용하지 않는다. 후보별 현재 원문과 일치 용어를 보고 체크한 뒤 범위를 지정한다. 기존 영향 범위와 현재 승인 필수 전제를 함께 포함하되 과거 그래프를 활성 승인으로 이전하지 않는다.

검색 전후 및 범위 지정 시 정본 전체 구조/hash·수정 전 원문·제안 hash·승인/채택 상태를 재검증한다. 변경/위조 결과는 거부한다. 범위 지정은 자동 전송·관계 승인·검사 완료·Issue 해결이 아니며 기존 전송 미리보기/예산과 전체 범위 Issue 해결 조건을 유지한다. 검색/후보 선택은 임시 UI 상태이고 새로고침 후 다시 수행한다. 실제 검토 실행의 checkedBlockIds만 검사 이력으로 저장한다. 스키마/백업 v15는 변경하지 않는다. 실제 영향 탐지의 재현율·대용량 성능·의미 계보·프로젝트 간 통합은 아직 미평가다.

### 대조 결과와 현재 채택 주장의 별도 승인 연결 (v16)

완료된 external-v1의 실제 대조 쌍에서 현재 버전의 채택 Claim을 명시 선택한다. 같은 블록이며 대조의 정확한 이론 인용을 Claim 원문이 포함해야 한다. 모델 분류와 달리 사용자가 supports/contradicts·네 분류·양쪽 조건·사유를 직접 정하고 원문과 모델 제안을 미리본 뒤 확인 승인한다. 자동 관계 채택·API 호출·외부 Claim 자동 추출·내부 검사/Issue 해결/캠페인 진행 변경은 없다.

ResearchRelation.externalReviewOrigin에 runId/pairId/contextHash/assessmentHash를 보존하고 relationHash에 포함한다. 원래 외부 결과는 변경하지 않는다. 원문/독립 역할·정본 전체 구조/hash·선택 인용·현재 채택을 재확인하고 트랜잭션에서 대조 결과/원문/정본 계보 변경·중복을 차단한다. 모델 제안과 사용자 승인 조건은 별개이며 Wiki·관계 이력·Markdown에서 계보를 표시한다. 내부 그래프 요청에는 외부 관계 원문을 포함하지 않는다.

Dexie v1–v15 유지 + v16/백업 v16. 복원 전 대조 쌍/Claim/SourceSpan 연결·원문 인용·문맥/모델 결과/관계 hash를 검증한다. 실패는 기존 작업공간을 보존하며 철회 이력도 계보를 유지한다. v15 이전 데이터에 계보를 조작해 채우지 않는다. 외부 Claim 추출·개념 및 프로젝트 통합·조건의 의미적 지지/실제 학술 평가·사용자 판정 정확도는 아직 미검증이다.

### 프로젝트 문서 조직 기반

기존 ResearchProject/TheoryDocument 스키마로 여러 독립 문서를 같은 프로젝트에 묶고 이름·대표 문서를 관리한다. 이동/분리는 조직 메타데이터만 바꾸며 정본 버전·각 문서의 전체 ResearchContract·Claim/검토/원문을 합치지 않는다. 대표 문서는 탐색 기준이지 프로젝트 전체 정합성 판정이나 다른 문서의 정본 승격이 아니다. 빈 출발 프로젝트 메타데이터 제거와 남은 문서의 대표 재지정은 확인 안내 후 원자적으로 수행한다. 이동/분리 동작 자체는 문서를 삭제하지 않으며 별도 삭제 흐름은 위의 근거 참조 조건을 따른다.

문서 버전/소속·목적지 대표 참조·프로젝트 이름 충돌을 확인하고 실패 시 롤백한다. UI의 미저장 변경/저장 중 이동·닫기·문서 전환을 차단한다. 프로젝트 이름 1–200자, 이동 시 프로젝트별 500문서·추가 생성 시 1,000프로젝트 제한을 둔다. 기존 1문서 프로젝트와 다중 문서 그룹은 백업 v16 참조 검증/원자적 복원을 유지하며 스키마 버전을 추가하지 않는다. 아직 프로젝트별 자료 허용 목록·RAG 검색/전송 정책·외부 Claim 추출·개념 및 교차 프로젝트 통합이 연결되지 않았으므로 이 조직 기능을 프로젝트 통합 전체 완료로 판정하지 않는다.

### 프로젝트 외부 대조 자료 허용 목록 (v17)

이 절은 외부 대조 전용 초판 기록이다. 현재 v18의 정본 RAG 명시적 확장은 아래 절을 따른다.

sourcePolicy는 scope=external_review·revision·allowedSourceIds로 저장한다. 최대 1,000자료, 명시 저장/확인, 빈 목록 전체 차단. 정책 없는 기존 및 미설정 프로젝트의 외부 대조는 이전의 명시 선택 흐름을 유지하며 UI에서 제한 없음으로 알린다. 목록에 있어도 메모/자체 문서는 독립 외부 증거가 아니다. 정책은 아직 일반 RAG·임베딩·내부 검토나 접근 제어에 적용되지 않는다.

외부 후보 목록 필터와 준비/예약/전송 직전/응답 후 및 새 관계 승인에서 현재 소속·허용 목록을 재검사한다. 정책 변경은 미리보기를 무효화하고 전송 중 변경은 실제 대조 0의 실패로 남긴다. 원문/미선택 자료를 추가 전송하지 않으며 고정 context에는 프로젝트 ID·개정 번호·정책 hash만 보존한다. 정책 원장 전체 이력은 아직 저장하지 않으므로 이 hash를 독립된 허용 감사 증명으로 승격하지 않는다. 과거 결과/관계는 이력으로 보존하되 새로운 승인은 현재 정책을 따라야 한다.

문서 이동에는 목적지 정책, 분리에는 출발 프로젝트의 제한을 승계한다. 개정/문서 충돌·누락/중복 원문 ID·quota 실패를 차단한다. Dexie v1–v16 유지 + v17/백업 v17; 정책 자료 참조·고정 context/hash 검증 후 원자적 복원하며 genuine v16에 정책을 만들어 채우지 않는다. 전체 프로젝트 RAG/임베딩 경계·자료 개정 정책·외부 Claim 추출/개념 통합·실제 학술 평가/대용량은 후속이다.

### 정본 기준 RAG의 프로젝트 정책 확장

이 절의 의미 검색 제한은 임베딩 연결 전 v18 단계 기록이다. 현재 의미 검색 경계는 다음 절을 따른다.

`external_review`는 외부 대조 전용으로 보존한다. 사용자 확인으로 `research`를 선택한 프로젝트만 동일 허용 목록을 정본 기준 RAG에도 적용한다. 검색 자료 전체를 검색 전 검사하고, 미리보기에 프로젝트 ID/정책 scope·개정/SHA를 고정하여 전송 전후 현재 정본·소속·정책·원문과 대조한다. 오래된 미리보기·허용 목록 밖 자료·전송 중 변경은 성공 완료 처리하지 않는다. 원문 없는 정본 단독 질문은 빈 허용 목록에서도 가능하다. 정책 통과는 학술적 독립성이나 이론 정합성 증명이 아니다.

정책 본문/미선택 허용 자료 ID는 요청에 넣지 않는다. 답변 근거와 Markdown·백업에는 전송 당시 scope를 보존하고 현재 프로젝트 정책과 독립적으로 이력을 복원한다. Dexie v1–v17 유지 + v18/백업 v18; genuine v17 외부 대조 전용 정책은 자동 확대하지 않는다.

정본 미선택 RAG와 임베딩은 작업공간 범위로 남는다. 정본 기준 검색에는 미연결 의미 검색/임베딩 전송 UI를 숨기고 BM25를 안내한다. 프로젝트별 임베딩 준비/전송 전후 검증·개정 정책/교차 프로젝트 Claim 통합·실제 학술 품질/성능은 후속이며 접근 제어 전체를 완료로 판정하지 않는다.

정책 본문 개정 원장/인증 서명은 아직 없다. 과거 정책 digest의 형식과 고정 기록은 복원하지만 당시 전체 허용 목록의 재구성/진위를 증명하지 않는다.

### 정본 기준 임베딩의 프로젝트 정책 연결

`research` 범위가 명시된 프로젝트의 정본을 선택하면 원문 색인/질문 임베딩 승인 미리보기에 문서 버전·프로젝트 ID와 정책 scope/개정/hash를 고정한다. 전체 선택 자료를 미리보기 전 검증하고 전송 전후에 확인한다. 원문 색인 각 배치의 수신 벡터는 게시 트랜잭션에서 정책을 다시 확인한다. 철회 중인 배치의 응답은 저장하지 않으며 앞서 성공한 체크포인트는 보존한다. 질문 응답 중 정책이 바뀌면 Worker 검색 결과를 게시하지 않는다.

공유 완성 색인/활성 포인터는 유지한다. 정본 기준 세대 활성화는 그 세대 전체 자료가 프로젝트 정책에 허용되는지 검사하고, 질문은 사용자가 이번에 선택한 자료의 벡터만 사용한다. 임베딩 제공사에 보내는 원문 요청은 선택 구간 텍스트만, 질문 요청은 선택 질문만 포함한다. 다른 허용 자료 ID/본문, PDF 원본, 정본·기존 대화는 전달하지 않는다. 정책 scope 미리보기는 로컬 일시 상태이며 백업/스키마는 v18을 유지한다. 정본 미선택 작업공간 임베딩에는 프로젝트 정책이 적용되지 않는다.

임베딩의 실제 문헌 품질·제공사 내부 revision·Float32/대용량·토큰/비용 원장과 정본 미선택 범위/교차 프로젝트 지식 통합은 남아 있다. 자료 정책 통과는 의미적 지지나 정합성 검사가 아니다.

### 정본 선택 전 프로젝트 자료 범위

정본이 없는 아이디어 단계에도 사용자가 프로젝트를 명시적으로 선택할 수 있다. 선택 프로젝트의 `research` 허용 목록으로 BM25 후보 검색, 원문 색인 배치, 질문 임베딩, 답변 원문을 검사한다. 다른 프로젝트의 자료나 허용 목록 밖 자료를 자동으로 섞지 않는다. 프로젝트/정본 모두 고르지 않으면 기존 작업공간 전체 선택 범위임을 안내한다.

ContextBundle의 `mode=project_only`는 프로젝트 ID·정책 scope/개정/hash와 검색 당시 원문·누락 범위를 고정한다. ResearchContract·정본 본문·승인 그래프는 첨부하지 않는다. 답변 근거/Markdown·백업에서 전송 당시 범위를 유지하고 손상된 mode/기준 조합은 복원 전에 거부한다. 색인/질문 승인 scope는 일시 상태로 현재 프로젝트 정책 변경 시 다시 생성한다. 공유 완성 색인/활성 포인터는 유지하지만 활성 세대의 전체 자료 허용과 이번 선택 자료만 쓰는 질문 검색을 구분한다.

Dexie/백업 v19는 기존 v1–v18을 읽고 과거 이력에 이 새 모드를 채워 넣지 않는다. 정책 본문 전 개정 원장/인증 서명, 실제 문헌 성능과 프로젝트 간 외부 Claim/개념 통합은 남아 있다. 정책 통과는 학술적 독립성이나 정합성 증명이 아니다.

### 선택 외부 원문 Claim 추출 후보

이 절의 원장/채택 부재 설명은 v19 후보 단계의 이력이다. 현재 채택 원장은 아래 v20 절을 따른다.

기존 `external-v1` 대조 쌍의 선택 SourceSpan에서만 모델이 외부 주장 후보를 제안한다. 후보는 요약 statement, 원문에 실제 포함된 `evidenceQuote`, 정의/이론/경험/기타 종류, 저자 진술/증명/실험/불명 근거 유형, 적용 조건을 갖는다. 인용 부분 문자열·종류·필수 길이/조건은 구조적으로 검증하지만 statement가 인용에서 논리적으로 따라오는지는 보증하지 않는다. PDF 수식·다단은 원본 페이지 대조가 필요하다.

후보가 없으면 `null`, 과거 외부 결과는 필드 부재를 허용한다. 보고서/백업에 모델 제안으로 보존하고 채택 Claim·사용자 승인 관계·독립 증거 또는 정합성 완료로 승격하지 않는다. 새 후보가 있는 대조의 결과 hash에는 후보가 포함되며 기존 결과 hash 계산은 유지한다. 아직 별도 외부 Claim 원장/채택, 개념 동치·충돌/교차 프로젝트 통합, 실제 문헌 추출 품질 평가는 없다.

### 외부 Claim의 사용자 채택 원장 (v20)

이 절의 프로젝트 전체 탐색 부재 설명은 원장 초판의 이력이다. 현재 탐색 경로는 아래 절을 따른다.

완료된 대조의 실제 쌍에서 검증된 Claim 후보를 별도 미리보기로 보여 주고 사용자가 원문과 조건을 확인한 뒤 채택한다. 프로젝트 ID, 문서/대조 run·pair ID, 평가 hash, 원문/구간 hash, 후보 본문, 시각·철회 사유를 기록하고 전체 기록 hash를 검증한다. 승인 전 현재 정본·프로젝트/허용 목록·독립 역할·원문을 재확인하며 저장 트랜잭션에서 동시 변경과 중복/한도를 거부한다. 과거 기록의 철회는 삭제가 아니라 별도 사유/시각을 남긴다.

Dexie/백업 v20은 v1–v19를 읽고 과거 기록에 채택을 소급 생성하지 않는다. 복원은 run/pair/평가·SourceSpan 참조와 기록 hash를 먼저 확인한 뒤 원자적으로 교체한다. 채택 원장은 모델 제안보다 강한 사용자 결정이지만 독립 출처의 학술적 타당성이나 주장의 참, 두 주장 사이 지지·상충, 이론의 정합성을 증명하지 않는다. 프로젝트 전체 탐색과 개념 동치/교차 프로젝트 관계는 아직 없다.

### 프로젝트 범위 외부 Claim 탐색

현재 프로젝트의 채택 원장만 조회해 정확한 인용·조건·문서/원문명으로 로컬 문자열 검색한다. 결과는 현재 범위와 철회/문서 이동/정본 버전 변경/정책 변경/원문 변경 이력으로 구분한다. 저장된 Claim·대조 문맥 hash를 검증하고 원문 본문/hash·SourceSpan/hash와 현재 정책 개정을 대조한 뒤 상태를 표시한다. 원본 출처 확인은 기존 페이지/구간 뷰를 재사용한다. 새 채택은 명시적 새로고침으로 반영한다.

이 화면은 프로젝트 간 원장을 자동 합치지 않으며 후보 검색만으로 개념 동치·지지·상충 또는 독립 증거의 진위를 판정하지 않는다. 이 절은 v20 탐색 초판의 이력이다. Dexie/백업 v20 유지 단계였으며 실제 대용량 지연은 아직 평가하지 않았다. 현재 명시적 교차 프로젝트 연결은 아래 절을 따른다.

### 명시적 교차 프로젝트 외부 Claim 후보 연결 (v21)

사용자가 비교할 다른 프로젝트를 선택해 현재 유효한 채택 Claim을 불러온다. 양쪽 주장·조건·원문·출처를 확인하고 후보 관계 유형과 조건별 메모를 정한 뒤 별도로 승인한다. 연결은 양쪽 프로젝트 ID, 채택 원장 ID와 승인 당시 hash, 관계 유형·조건·메모·시각·철회 이력 및 기록 hash를 독립적으로 보존한다. 어느 한쪽의 철회, 문서 이동, 정본·정책·원문 변경은 현재 연결을 stale로 만든다. 새 승인 시 양쪽 원장과 출처를 재검증하고 저장 시점에 다시 스냅샷을 비교한다.

연결은 `same_concept_candidate`, `different_scope_candidate`, `conflict_candidate`, `related`의 **사람이 남긴 후보 표시**다. 동치·상충의 의미 검증도, 사용자 간 접근 제어도, 검색·LLM 문맥에 자동 편입하는 그래프도 아니다. 과거 연결의 존재만으로 외부 문헌을 독립 증거로 재승격하지 않는다. Dexie/백업 v21은 v1–v20을 가져오며 기존 버전에는 연결을 소급 생성하지 않는다. 후속 단계는 개념 정규화/의미 후보 탐색, 범위 조건의 의미 대조, 프로젝트 권한 경계, 실제 문헌의 사람 판정 품질 평가다.

### 교차 프로젝트 외부 Claim 어휘 후보

사용자가 상대 프로젝트의 현재 채택 원장을 명시적으로 불러온 경우에만, 선택한 현재 주장 문장을 질의로 로컬 BM25 점수를 계산한다. 공통 용어와 상위 12개를 표시하고 과거/철회/다른 범위 주장은 제외한다. 점수는 어휘 겹침일 뿐 개념 동치·논리적 지지·상충 판단이 아니다. 후보를 고르면 상대 주장 선택값만 바뀌며 양쪽 원문 확인·조건 입력·명시 승인과 변경 재검증은 그대로 필요하다. 목록 밖 주장도 수동으로 고를 수 있다. 제공사 전송이나 스키마 변경은 없다. 번역/동의어/수식 동치와 실제 사람 판정 재현율·대용량 지연은 후속 평가 대상이다.

### 연구 기준의 정본 원문 블록 연결 (v22)

연구 기준 항목별로 사용자가 저장된 현재 정본 버전의 한 블록을 출처로 지정한다. 버전에는 항목→블록 ID/hash 연결을 불변 보존한다. 기준 문구가 비면 연결할 수 없고, 본문이나 항목이 바뀌어 원문 연결이 더는 동일하지 않으면 새 버전에서 연결을 제거하거나 명시적 재선택을 요구한다. 기존 문서의 연결은 자동 추론하지 않는다. RAG 답변의 고정 ContextBundle에는 연결 메타데이터만 기록하고, 선택하지 않은 정본 블록의 본문은 제공사로 보내지 않는다. 사용자는 연결을 바탕으로 원문을 확인할 수 있지만 연결 자체가 기준의 참·의미적 지지·이론 정합성을 보증하지 않는다.

Dexie/백업 v22는 v1–v21을 읽고 빈 연결로 이전한다. 복원 전에 항목·버전·블록/hash를 검증하며 실패 시 기존 작업공간을 유지한다. 첫 연결은 기존 문서를 저장한 뒤 가능하다. 여러 근거 블록·정확 발췌 범위·검토 범위 자동 의존성 연결·의미 검증은 남는다.

### R6 검색 지연의 첫 합성 기준선

1만/5만 구간의 Node BM25 토큰화·점수 계산, Chromium Worker 입력 복제/검색/결과 왕복, IndexedDB 자료 선택→새 Worker 검색을 각각 반복 측정한다. 측정 스크립트와 단일 실행 수치는 [성능 측정 기록](./PERFORMANCE_BASELINE.md)에 둔다. DB 기준선에도 원문/hash 무결성 검사·벡터/RRF·선택 미리보기·UI long task/메모리·1만 메시지가 빠져 있으며 실제 문헌 질의 품질이나 전체 제품 p95의 대용치가 아니다. 이후의 측정에서 기준 장치·자료 분포·표본 수와 추정 오차를 함께 기록한다.

### 독립 라벨의 실문헌 검색 평가 입력

실제 문헌 품질 평가를 위해 작업공간 백업의 자료·구간과 별도 질문/정답 JSON을 받는 로컬 경로를 둔다. 평가 전 선택 자료/정답 구간의 ID·SHA-256·원문 오프셋, 질의별 명시적 검색 범위와 개발/보류 분할을 검증한다. 조건에 맞으면 기존 BM25 기준선의 Recall@5/20·MRR·근거 없음 정확도·범위 밖 회수를 출력한다. [입력 계약](./REAL_RETRIEVAL_EVALUATION.md)을 따른다. 이는 평가기 준비일 뿐 실제 라벨 확보·독립성 확인·벡터/그래프/재정렬 비교 또는 이론 정합성 수용이 아니다.

### 세 창 상단바 버튼 이름·대화 삭제 확인 (2026-10-04)

좌측 탐색기·가운데 문서 창·오른쪽 대화창의 상단바 버튼에 hover/focus-visible 툴팁을 추가했다. 대화 기록 삭제는 브라우저 기본 확인창에서 취소·삭제 전까지 유지되는 앱 내부 모달로 바꾸고 대상 세션·메시지 수, 포커스 복귀와 키보드 순환을 제공한다. 이는 조작 UI 변경이며 선택 원문·ContextBundle·정본 버전·ResearchContract·인용·LLM 전송 범위와 기존 원자적 세션 저장 계약은 변경하지 않는다. 전체 단위 44파일/320개(2개 skip), lint, production build, Chromium hover 및 삭제 취소/확정/재시작 보존 E2E 각 1개와 `git diff --check`를 통과했다. 실제 API·원격 CI·배포·commit/push는 수행하지 않았으며 OCR은 비목표다.

### 상단바 표시 단순화와 안내 블록 제거 (2026-10-04)

오른쪽 대화 상단바의 제목 편집 아이콘은 오른쪽 버튼 그룹 맨 앞, 대화 기록 버튼 왼쪽에 배치하고 hover/focus-visible에 `제목 변경`을 표시한다. 제목은 아이콘을 눌러 모드 옆 입력창을 펼치는 방식으로 축약하고, 가운데 프로젝트명은 표시 전용으로 바꿨다. 문서 제목 편집 아이콘의 상시 가시성을 높이고 기능 없는 `LLM Research Wiki` 사이드바 안내를 제거했다. 레퍼런스 검색, 정본 문서, Claim/Wiki 데이터, 선택 원문·ContextBundle·ResearchContract·인용·LLM 전송 계약은 삭제하거나 변경하지 않는다. 전체 단위 44파일/320개(2개 skip), lint, production build, Chromium 프로젝트 흐름 E2E 1개와 `git diff --check`를 통과했다. 실제 API·원격 CI·배포·commit/push는 수행하지 않았으며 OCR은 비목표다.

## 10. 평가와 완료 기준

연구자가 정답 근거와 예상 Issue를 표시한 초기 60개 사례를 만든다. 사실·정의 검색, 한국어 질문/영문 원문, 여러 절의 의존성, 반례, 범위 차이, 근거 없음, 과거 버전·재첨부 문서를 균형 있게 포함한다. 튜닝용과 보류 평가용을 분리하고 결과를 질의 유형별로 보고한다.

현재 구현은 그 실제 문헌/Issue 평가에 앞선 **합성 회귀 기준선**이다. 12개 합성 원문·32개 블록에 수동 고정한 60질의(개발 39/보류 21)를 사용한다. 질의 분할만 수행했으며 미공개 원문·연구자 판정·블라인드 평가는 아니다. 기본 검색 범위는 의도적으로 제외한 원문 1개를 뺀 11개 원문·30개 블록이다. 평가에서 후보 20개를 요청하지만 앱 UI는 기존대로 12개 후보를 표시한다. 결과와 한계는 [검색 평가 기록](./RETRIEVAL_EVALUATION.md)에 남긴다. 이 합성 평가 결과를 아래 제품 수용 목표 달성으로 승격하지 않는다.

아래 수치는 **초기 수용 목표**이며 현재 달성 결과가 아니다. 목표 변경은 평가 세트와 변경 이유를 함께 기록한다.

| 영역 | 초기 수용 기준 |
| --- | --- |
| 버전·데이터 무결성 | 테스트에서 옛 정본 혼입·자기 문서 외부 근거 승격·깨진 인용 ID 0건 |
| 검색 | 레이블된 근거 Recall@20 ≥ 0.90; 유형별 점수와 BM25 기준선 함께 보고 |
| 필수 의존성 | 선언된 필수 정의·전제는 포함하거나 초과·누락을 명시; 조용한 누락 0건 |
| 인용 | ID/원문 위치 유효성 100%; 사람 검토 의미적 지지 정확도 목표 ≥ 0.95 |
| 결정적 검사 | 지원 규칙별 fixture의 예상 오류 탐지·정상 통과 모두 성공 |
| LLM Issue | 심은 중대 오류 Recall ≥ 0.85, Issue Precision ≥ 0.80; 사람 판정 기준 사용 |
| 수정 반복 | stale Patch 거부, 새 가정 표시, 과거 해결 오류 재발 감지, 예산·중단 테스트 통과 |
| 로컬 성능 | 기준 장치·브라우저를 기록하고 1만 메시지/1만·5만 청크에서 검색 p95·메모리·UI long task 측정 |

검색 성능의 임시 목표는 1만 청크 warm 로컬 검색 p95 500 ms 이내다. 임베딩 모델 로드, 질의 임베딩, 네트워크·LLM 시간은 따로 측정한다. 메시지 수와 벡터 수를 같은 부하 지표로 취급하지 않는다.

BM25, BM25+벡터, BM25+그래프, 세 방식 결합을 같은 사례로 비교한다. 그래프나 재정렬이 품질·비용에 주는 효과를 측정한 뒤 기본 활성화 여부를 결정한다.

| R4 — 의미 검색 (초판·완성 세대 전환 구현) | 승인형 임베딩·세대/hash 캐시·Worker 코사인/RRF·범위 기록·원자적 활성/과거 세대 재선택. 재정렬·실제 평가 잔여 | 승인 → 증분 색인 → 완성 검증/활성 승인 → 질문 승인 → 근거/답변/복원 → 실제 기준선 비교 |
| R5 — 관계 확장 (승인 관계/Wiki 초판) | 같은 정본 버전의 채택 Claim/선택 원문 승인 관계·역참조/영향·원문/Wiki·수동 조건 대조. 그래프 RAG/검토·레퍼런스 Claim/LLM 대조 잔여 | 관계 미리보기/승인 → 원문·역참조·영향 → 변경 시 stale/명시 재확인 |
| R6 — 고도화 | 대용량 최적화·필요 시 ANN, 수학 도구, 전체 검토 범위 보고 | 큰 문서의 반복 수정과 재개, 적용 가능한 수학 검증 결과 확인 |

첫 사용 가능한 연구 루프는 R1–R3다. R4–R5가 목표 하이브리드 RAG를 완성한다. 저장소 1만 메시지 성능 과제는 유지하고 R1의 기반 측정 및 R6의 최적화에 연결한다. GitHub Actions와 배포는 사용자의 기존 결정에 따라 보류한다.

R1은 문서마다 프로젝트를 자동 생성하는 최소 구조다. ResearchContract는 사용자가 직접 입력하며 현재는 저장된 버전의 블록 하나를 항목별로 명시 연결할 수 있다. 자동 추출·다중 블록 근거는 아직 없다. 블록은 제목·문단·fenced code·블록 수식으로 분할하고 원문 문자 범위와 SHA-256을 보존한다. 단순 1:1 수정은 ID를 유지하고 분할·병합 후보는 이전 블록 ID 목록으로 계보를 남긴다. 이는 의미적 동일성이나 정합성 판정이 아니다.

R2 첫 구현의 제한과 결정:

- PDF는 20 MB·300쪽·추출 텍스트 200만 자 제한이다. `pdfjs-dist@6.3.289`를 지연 로드하고 전용 Worker에서 해석한다. CMap/글꼴/WASM은 앱과 같은 출처의 정적 자산이며 별도 CDN이나 모델로 원본을 보내지 않는다.
- PDF 원본 ArrayBuffer/hash, 페이지별 추출 결과, 엔진 버전과 진행 상태를 보존한다. 모든 페이지 처리가 끝난 뒤 검색 자료를 원자적으로 게시하며 취소·실패 중간 결과는 검색하지 않는다. 재개는 같은 엔진 버전의 완료 페이지 다음부터 수행하고 버전이 바뀌면 처음부터 추출한다. run ID로 이전 실행의 후발 쓰기를 막는다.
- 상태는 pending/running/ready/partial/ocr_required/encrypted/failed/cancelled다. `ocr_required`는 호환용 상태명이며 OCR 구현 예정이라는 뜻이 아니다. 텍스트가 없는 페이지는 스캔 또는 빈 페이지일 수 있고 검색 범위에서 제외한다. 혼합 문서의 누락 페이지 번호를 미리보기와 모델 입력에도 포함한다. 암호화 문서는 암호를 받거나 저장하지 않고 사용자가 해제한 사본을 등록하게 한다.
- 추출 순서는 PDF.js의 텍스트 항목 순서를 유지한다. 다단/표/수식의 의미적 읽기 순서와 좌표별 인용 강조는 미구현이다. 인용에서 해당 PDF 페이지를 canvas로 렌더링해 대조하며 문서의 스크립트·링크 동작을 실행하는 UI는 제공하지 않는다. OCR은 비목표다.
- 원본과 텍스트 hash를 구분한다. 같은 텍스트를 가진 서로 다른 PDF는 별도 원본으로 유지하며 텍스트 파일 중복 판별과 혼합하지 않는다. 백업 v4는 원본을 base64로 포함하고 복원 전 바이트·추출문·페이지·인용 관계를 검증한다. 가져온 running 작업은 소유자를 제거한 cancelled 상태로 바꾸어 명시적으로 재개한다. 전체 JSON 100 MB 초과 백업은 차단하며 분할 백업은 아직 없다.
- UTF-8 Markdown/TXT 파일당 2 MB. 제목·문단·코드·수식 블록을 기본으로 최대 2,400 UTF-16 문자에서 나누며 surrogate pair와 원문 위치를 보존한다. ATX 제목의 상위 제목들과 가장 가까운 섹션을 회수하고 fenced code 내부 제목은 제외한다. 제목 없는 TXT는 부모 구조를 추론하지 않는다. PDF는 동일 페이지의 구간만 추가하며 수학적 의미 경계·의존성·페이지 간 연결은 추론하지 않는다.
- BM25는 `k1=1.2`, `b=0.75`, 양수 IDF `log(1 + (N-df+0.5)/(df+0.5))`를 사용한다. NFKC·소문자 단어 및 한글 2-gram 기준선이며 형태소 분석·번역·의미 검색을 제공하지 않는다. Worker가 선택 문서의 색인을 요청마다 재생성한다.
- 최대 12개 검색 후보에서 사용자가 전송 근거를 선택한다. 별도로 선택한 정본 버전의 ResearchContract 전체를 검색 순위와 무관하게 고정하며 정본 본문 전체는 전송하지 않는다. 기준 미선택/빈 항목은 완전성 미확인으로 표시한다. 선택 근거와 연구 기준 메타데이터 합계 12,000 UTF-16 문자 초과는 차단한다. 선택 근거를 먼저 유지한 뒤 부모 문맥을 총 8구간/문자 예산까지 추가하고 제외 구간 ID·원문 위치·파일명·사유를 미리보기/모델 입력/답변/내보내기에 남긴다. 문자열이나 핵심 전제를 자동 절단하지 않는다.
- 질문·대화·근거·누락 메타데이터 직렬화에 UTF-8 48 KB 애플리케이션 한도를 추가 적용한다. 큰 섹션에서는 누락 목록 자체가 이 한도를 넘을 수도 있다. 모델별 tokenizer·출력 예산, 정의/가정 블록 ID의 정확 의존성 회수는 후속 작업이다. 선택 기준은 목록을 열 때의 정본 버전으로 고정되고 이후 버전으로 조용히 교체하지 않는다.
- 검색 자체는 네트워크 요청이 없다. 모델과 전송 원문 미리보기 후 명시적 질문 전송 시에만 기존 대화와 선택 발췌를 제공사에 보낸다. 원문의 지시는 신뢰하지 않는 인용 데이터로 구분하지만, 이것이 프롬프트 주입의 완전 차단 보장은 아니다.
- 불변 source ID/hash와 span으로 답변 근거를 저장한다. 재시도는 같은 묶음을 사용하고, 인용 ID 불일치·인용 누락을 경고한다. 원문 보기에서는 해당 hash와 발췌 일치를 다시 확인한다. 인용의 의미적 지지는 아직 검사하지 않는다.
- 외부 문헌/메모/자체 문서를 구분하고 정본과 같은 hash는 자체 문서로 연결한다. 수정된 자체 문서·외부 문헌의 개정 계보, 프로젝트별 허용 자료와 과거 버전 기본 필터는 후속이다. 현재 사용자가 이번 질문의 source ID를 명시적으로 선택한다.

현재 R3 초판은 문서 내 선택 블록과 ResearchContract만 전송하며 기존 대화/레퍼런스/PDF 원본은 보내지 않는다. 원문이 없는 인용·미선택 블록·알 수 없는 종류·미검사 범위를 숨기는 출력은 거부하거나 판단 불충분으로 표시한다. LLM이 전체 범위를 검사했다고 보고해도 의미적 지지/정합성 보증으로 승격하지 않는다. 새 가정은 모델의 선언을 명시적으로 보여 주고 승인 시 연구 기준에 추가하지만 숨은 가정을 자동으로 증명해 찾아내지는 못한다. 수정 전 hash와 현재 버전을 쓰기 트랜잭션에서 확인하고 승인 메타데이터와 버전을 함께 저장한다. 실패하면 둘 다 롤백한다. Issue는 적용만으로 닫지 않고 후속 같은 검사 종류의 전체 범위 통과 뒤 사용자 확인으로 해결 표시한다.

다음은 **R5 외부 Claim의 의미 기반 개념 통합·의미 의존성, R4 재정렬·실제 평가**다. 기존 외부 대조의 선택 구간에서 Claim 후보를 검증/표시/복원하고 별도 승인으로 원장에 채택·철회하며 현재 프로젝트 안에서 상태별로 탐색한다. 사용자가 다른 프로젝트의 현재 채택 주장과 양쪽 원문·조건을 확인해 별도 후보 관계를 승인/철회할 수 있다. 과거 대조 결과와 관계 hash는 유지한다. 이 연결은 자동 LLM 근거·동치 확정·의미적 지지 검증이 아니다. R3 구조적 반복 제어·R4 색인 전환·R5 승인 관계/Wiki·그래프 분할·수정 영향·독립 원문 대조·미선언 영향 어휘 후보·대조 결과의 별도 관계 승인 연결은 구현되었으나 의미적 반복·구간 간 논증·미선언 관계 추출·조건/단위 의미 검증은 남아 있다. 전체 범위는 [감사표](./SERVICE_COMPLETION_AUDIT.md), 검증은 [완료 기록](./completed.md)에 유지한다. 실제 품질·모델별 토큰/비용·대용량 성능은 미평가다. PDF Worker 약 1.27 MB는 JS 500 kB 예산의 잔여 예외다.

### 오른쪽 대화의 문서 기준선 (2026-10-04)

가운데 연구문서의 상단바 `닫기` 버튼을 제거해 우발적으로 기준 문서를 빈 화면으로 바꾸는 동선을 줄였다. 문서 ID·버전·ResearchContract와 전송 범위는 바뀌지 않는다. 다른 문서 선택·새 문서 생성 시 미저장 변경 확인은 아직 없으므로, 이 UI 변경만으로 초안 손실 방지를 보증하지 않는다.

오른쪽 대화는 열린 정본 문서의 ID를 세션 소유자로 저장하고 해당 문서의 기록만 표시한다. 연구 질문에는 전송 당시 문서 전체 또는 미저장 초안 전체를 본문/hash/ResearchContract와 함께 고정한다. 이는 이전 R2 검색 경로의 “정본 본문 전체를 전송하지 않는다”는 선택 근거 한정 계약과 별개의 일반 대화 경로다. 선택하지 않은 레퍼런스/PDF 원본은 여전히 보내지 않는다. 일반 문서 대화 안전 한도는 UTF-8 512 KB, 근거 선택 RAG 한도는 48 KB다. 어느 쪽도 제공사별 정확 토큰 계산·수락을 보증하지 않으며 원문을 자동 절단하지 않는다.

일반 대화의 짧은 질문만 같은 제공사의 경량 모델로 문서 없이 분류한다(OpenAI `gpt-4o-mini`, Gemini `gemini-3.5-flash-lite`, Claude `claude-haiku-4-5-20251001`). 명백한 인사는 분류 호출 없이 경량 답변으로 처리한다. 분류 실패·모호성은 연구 경로로 보수적으로 복귀한다. 경량 답변은 세션에만 문서 소속을 유지하고 문서 본문을 전송/첨부했다고 표기하지 않는다. 이 라우팅의 품질·실제 비용 절감·모델별 장문 수용은 미평가다. UI를 바꾸지 않는 이번 범위에서 전송 직전 전체 문맥 미리보기와 경량 라우팅 선택 제어는 미구현으로 남는다.

오른쪽 대화 답변의 모델명·모드 배지·장식 아이콘을 화면에서 제거하더라도 저장된 답변의 모델/모드, 전송 문맥, 원문 인용과 오류·재시도 기록은 유지한다. 답변 본문은 테두리 없는 12px 텍스트로 표시하고 복사 아이콘을 답변 끝에 둔다. 이는 표시 변경이며 RAG 선택·전송·검증 계약을 바꾸지 않는다.

## 12. 근거와 남은 선택

- [PDF.js 공식 예제](https://mozilla.github.io/pdf.js/examples/) 및 [API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html): 로컬 바이트 입력, Worker·페이지별 텍스트 추출과 canvas 렌더링 계약을 참고하고 설치 패키지 타입/브라우저 테스트로 확인했다.
- [Stanford IR Book — Okapi BM25](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html): 빈도 포화·길이 정규화와 IDF를 사용하는 검색 기준선의 근거. 로컬 구현은 작은 선택 집합에서도 음수 가중치를 피하도록 양수 IDF 변형을 사용한다.
- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval): 문맥을 보완한 청크와 BM25·임베딩·재정렬 조합을 평가한 사례다. Qaxiom의 효과는 자체 평가로 확인한다.
- [Microsoft GraphRAG Local Search](https://microsoft.github.io/graphrag/query/local_search/): 그래프 관계와 연결된 원문 청크를 함께 회수하는 구조를 참고했다. Qaxiom은 이를 주장·전제 관계와 버전 관리에 맞게 적용한다.

현재 원격 임베딩 초판은 OpenAI text-embedding-3-small/512차원이며, 전용 벡터 DB·로컬 임베딩 대안·한국어 토크나이저·재정렬 모델은 아직 선택하지 않았다. 한영 검색 품질, 다운로드 크기·메모리, 로컬 실행 가능성, 데이터 전송 범위와 비용을 R4 벤치마크에서 비교한다. 위 근거 문서는 검색 설계를 뒷받침하며, 이론 정합성을 보증하는 자료는 아니다.
