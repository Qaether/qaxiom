# 고정 검색 회귀 평가

기준일: 2026-10-03. 재실행: `npm run test:retrieval`.

## 범위와 판정

합성 연구 문단 12개 원문·32개 블록과 수동 고정한 60질의의 로컬 BM25 기준선이다. 기본 선택은 11개 원문·30개 블록이며 제외 원문의 고유 용어는 회수하지 않아야 한다. 정의 10, 한국어 10, 혼합 언어 10, 기호 5, 범위 5, 반례 5, 과거/현재 버전·메모 선택 5, 근거 없음 5, 교차언어 5로 구성했다.

개발 39/보류 21은 고정 질의 단위 분할이며 같은 합성 corpus를 공유한다. 실제 논문·사용자 연구의 정답, 독립 연구자의 라벨, 미공개 corpus나 블라인드 평가가 아니다. R3 Issue 정확도와 인용의 의미적 지지는 측정하지 않는다. 기대 span ID는 검색 결과에서 생성하지 않고 fixture에 명시했다.

## 기준선 결과

| 범위 | 질의 수 | Recall@5 | Recall@20 | MRR |
| --- | --- | --- | --- | --- |
| 전체 | 60 (관련 근거 있음 55) | 0.9273 | 0.9273 | 0.9273 |
| 개발 | 39 (관련 근거 있음 36) | 0.9444 | 0.9444 | 0.9444 |
| 보류 | 21 (관련 근거 있음 19) | 0.8947 | 0.8947 | 0.8947 |
| 교차언어 | 5 | 0.2000 | 0.2000 | 0.2000 |

나머지 관련 근거 유형의 Recall@20은 1.0이다. 근거 없음 5질의의 무결과 정확도는 1.0, 선택 범위 밖 회수는 0건이다. Recall은 정답이 있는 질의만 대상으로 질의별 회수 비율을 평균한다. MRR은 첫 정답 순위의 역수이며 역시 관련 근거 질의를 대상으로 한다. 전체 macro Recall은 유형별 표본 수에 영향을 받으므로 교차언어의 실패를 전체 수치로 가리지 않는다.

정답을 찾지 못한 질의는 `cross_language-1`, `-2`, `-4`, `-5`다. 한국어 질문이 영문 원문 용어와 겹치지 않으면 현재 토크나이저는 번역/의미 연결을 하지 못한다. R4 임베딩·RRF 비교 시 이 실패 사례를 유지한다. 보류 Recall@20은 0.90 미만이며 합성 전체 수치로 제품 수용 목표를 달성했다고 판단하지 않는다.

로컬 Node v25.9.0/macOS arm64의 소규모 동기 평가 한 차례에서 검색 p95 약 0.56 ms를 관측했다. 이는 매 질의 BM25를 재구성한 순수 검색 시간이며 Worker 전달·UI·네트워크·임베딩·모델·부모 문맥 확장은 제외한다. 실행 부하/초기 워밍에 따라 변하며 1만/5만 청크의 warm p95 500 ms 목표를 검증한 결과가 아니다. CLI는 매 실행 실제 시간을 출력하고 시간 기준은 단위 테스트의 통과 조건으로 고정하지 않는다. 별도 1만/5만 합성 구간의 JS/브라우저 Worker 기준선은 [성능 측정 기록](./PERFORMANCE_BASELINE.md)에 둔다.

## 별도 문맥 무결성 회귀

`assembly.test.ts`와 PDF/레퍼런스 E2E는 선택 정본의 검색어 없는 필수 가정 포함, 빈 계약 항목 보고, 부모 범위/코드 fence/PDF 페이지 경계, 중복 제거, 모든 예산 누락 구간의 위치 기록, 기준 초과 시 무절단 차단, 버전 고정 및 손상 복원 거부를 검사한다. 이는 수학적 의존성이나 이론의 정합성을 검증하지 않는다.

## 다음 평가

실제 작업공간 백업과 별도 사람이 만든 라벨을 검증·평가하는 로컬 입력 계약은 [실문헌 평가 안내](./REAL_RETRIEVAL_EVALUATION.md)에 있다. 아직 해당 corpus·라벨을 받아 실행한 결과는 없다.

- 연구자가 실제 문헌과 이론 문서의 정답 근거를 표시한 사례를 별도로 확보한다.
- 정의·가정의 원문 블록 연결과 여러 절/페이지 의존성, 개정 재첨부 계보, 오답·범위 차이를 확장한다.
- 같은 보류 질의를 BM25/벡터/그래프 조합에 사용하고 유형별 개선과 퇴행을 보고한다.
- Claim/Issue 정답은 R3 이후 별도로 레이블하고 사람 검토 기준으로 검증한다.
- 큰 문서 성능과 모델별 tokenizer/출력 예산은 별도 과제로 측정한다.
