# Qaxiom 연구노트 UI와 UX 재설계 계획

> 상태: 프로젝트/폴더 선택 기억과 단일 문서 작성 흐름 구현, 폴더 정본 저장과 폴더 내용 재열기는 미구현 · 2026-10-03  
> 범위: 데스크톱 웹의 프로젝트 시작·로컬 폴더의 Markdown 정본 저장·연구노트 작성·AI 분석·수정 반복. 모바일 반응형 추가 개발, OCR, 배포는 범위 밖이다.

Qaxiom의 주 작업은 프로젝트를 정해 로컬 폴더에 저장하고, 그 안에서 아이디어나 초안을 연구노트로 발전시키며, AI의 지적을 원문과 대조해 새 버전을 반복 검토하는 것이다. 첫 사용자는 RAG, 그래프, 연구 기준, 검토 회차를 알 필요가 없어야 한다. 이 계획은 **사용자에게 보이는 흐름의 기준 문서**다. 기존 [구현 계획](./IMPLEMENTATION_PLAN.md)과 [RAG 설계](./RAG_DESIGN_PLAN.md)는 현행 코드·데이터 계약의 기록으로 유지하되, 화면 구성과 작업 우선순위가 충돌하면 이 문서를 따른다. 구현 완료 여부는 [완료 내역](./completed.md)에서 별도로 확인한다.

## 사용자가 끝내야 하는 일

1. 처음 앱을 열면 프로젝트 설정·선택 화면이 뜬다. 프로젝트를 결정한 뒤 해당 프로젝트의 **로컬 폴더**를 지정한다. 새로고침 시 폴더 권한이 유효하면 채팅으로 돌아가고, 권한 재승인이 필요하면 기억된 프로젝트에서 폴더를 다시 연결한다.
2. 프로젝트가 열리면 채팅 화면이 나온다. 사이드바의 `+ 새 연구노트`에서 제목과 본문을 입력하거나 기존 문서를 연다. 저장만으로 AI 호출은 일어나지 않는다.
3. 문서를 저장한 뒤 `AI로 분석`을 누르면 모델, 전송할 문서 구간·자료와 빠진 범위를 확인하고 사용자가 실행을 승인한다. 문서별 연구 특화 모드 선택은 실제 문서 상태와 분석 방식에 연결한 뒤 제공한다.
4. 결과에서 **핵심 요약 → 확인할 문제 → 근거가 붙은 주장·가정·정의 후보 → 수정 제안** 순서로 읽고 원문 위치로 돌아간다.
5. 사용자가 직접 고치거나 수정 제안을 비교해 적용한다. 적용은 새 버전으로 저장되며 원본과 이전 결과는 남는다. 바뀐 버전을 다시 분석하고, 미검사 범위는 계속 표시한다.

대화 기록은 지금처럼 남겨 아이디어 탐색에 사용한다. 다만 **연구노트의 저장된 버전이 정본**이다. 대화 답변을 문서 초안으로 가져올 수 있지만 자동으로 정본·외부 근거가 되지 않는다. 여러 연구노트를 종합해 논문을 만드는 작업은 후속 단계의 별도 버튼과 흐름으로 설계한다. 이 계획에서 논문 생성 기능을 선행 조건으로 두지 않는다.

## 화면 구조와 이동

| 화면 | 주 역할 | 가장 중요한 조작 | 주 화면에서 치울 것 |
| --- | --- | --- | --- |
| 프로젝트 시작 화면 | 프로젝트를 만들거나 고르고 로컬 폴더를 연결한다 | `프로젝트 만들기`, `프로젝트 열기`, `폴더 지정` | 채팅·문서 작업을 시작한 것처럼 보이는 상태 |
| 프로젝트 채팅 화면 | 아이디어를 논의하고 대화 기록을 본다 | `+ 새 연구노트`, 대화 입력 | 별도 `연구노트` 진입 버튼, 문서 작성 전의 연구 특화 모드 |
| 문서 작업 화면 | 하나의 문서를 읽고 쓴다 | `저장`, `AI로 분석` | 프로젝트 정책, 여섯 연구 기준 입력란, 검토 예산 설정 |
| 전송 확인 화면 | 제공사 전송을 명시적으로 승인한다 | `이 범위로 분석 시작`, `취소` | 원시 JSON과 hash를 기본 본문에 노출 |
| 분석 결과 화면 | 문제를 이해하고 수정한다 | 원문으로 이동, `수정안 비교`, `다시 분석` | 실행 ID, 모델 파싱 세부사항, 긴 로그 |
| 자료 화면 | 필요할 때 독립 문헌을 추가·검색한다 | `자료 추가`, `이 문서 검토에 사용` | 문서 편집 전의 필수 자료 등록 |

데스크톱에서는 프로젝트 선택·폴더 연결 뒤 현재와 같은 채팅 화면을 기본으로 연다. `+ 새 연구노트` 또는 문서 목록에서 문서를 열면 작은 모달이 아닌 **독립 작업 화면**으로 전환한다. 문서 작업 화면의 왼쪽은 문서 목록, 가운데는 읽기·편집, 오른쪽은 현재 작업에 필요한 분석 결과를 둔다. 오른쪽 패널은 분석 전에는 비우거나 짧은 안내만 보여 준다. 긴 결과를 다룰 때는 결과 전용 화면으로 전환하되 문서의 같은 위치로 쉽게 돌아온다. 넓이가 충분하지 않은 데스크톱 창에서는 패널을 순차 전환하고 작성 내용을 유지한다. 이는 모바일 모드 개발을 재개한다는 뜻이 아니다.

채팅 사이드바에는 현재 프로젝트, `+ 새 연구노트`, 프로젝트의 연구노트 목록, 기존 대화 기록, 레퍼런스 관리와 설정을 둔다. 별도 `연구노트` 버튼은 제거한다. 연구 특화 모드는 향후 문서 작성·수정 화면에서만 활성화하고 선택값을 문서에 연결한다. 현재 채팅 세션 모드만 바꾸던 문서 화면의 잘못된 선택기는 제거했다. 기존 대화의 모드와 내용은 보존하고 일반 채팅 기능도 유지한다. 문서 화면 상단에는 현재 문서명, 저장 위치와 버전, `저장`, 저장 후 `AI로 분석`만 우선 노출한다. `Wiki`는 별도 진입 버튼이 아니라 문서의 `개념과 주장` 보기이며, 그래프는 근거 관계를 이해할 때 여는 선택적 보기다. `프로젝트 설정`, `연구 기준 편집`, `고급 검색·검토 기록`은 해당 작업의 메뉴에서 열고 처음 작성할 때 요구하지 않는다.

## 화면별 동작

### 프로젝트 시작과 로컬 폴더

처음 앱을 열면 프로젝트 설정·선택 화면이 나타난다. 새 프로젝트는 이름을 정한 뒤 로컬 폴더를 지정해야 열 수 있다. 선택한 프로젝트와 폴더 핸들은 브라우저 DB에 기억한다. 새로고침 후 읽기·쓰기 권한이 유효하면 채팅으로 복귀하고, 재승인이 필요하거나 거부되면 기억된 프로젝트를 보여 주고 사용자의 `폴더 다시 연결` 조작을 기다린다. 폴더 선택을 취소하거나 권한이 없으면 채팅 화면으로 넘어가지 않는다. 사용자가 다른 프로젝트를 고를 수도 있어야 한다. 폴더 이름·연결 상태는 보여 주되 브라우저가 알려 주지 않는 전체 경로를 가진 것처럼 표시하지 않는다.

**설계 결정:** 지정한 폴더는 단순 내보내기 대상이 아니라 프로젝트의 실제 저장 위치다. 연구노트의 현재 본문은 사람이 다른 편집기로도 열 수 있는 `.md` 파일을 정본으로 둔다. 이전 버전의 본문도 별도 `.md` 파일로 보존한다. 프로젝트 식별·버전 계보·검토 판정·출처 연결·대화 기록 등 Markdown 본문만으로 복구할 수 없는 구조화 정보는 같은 프로젝트 폴더의 보조 파일에 둔다. 보조 파일 형식은 저장 계약에서 정하되, 연구노트 본문을 JSON만으로 저장하지 않는다. 레퍼런스 PDF 원본은 PDF로 유지한다. 이 자료들을 합쳐 프로젝트를 폴더만으로 복원할 수 있어야 한다.

브라우저 내부 DB는 검색·성능용 캐시 또는 안전한 쓰기 준비 공간으로만 쓰고, `.md` 파일과 필요한 보조 기록의 쓰기가 확인되기 전에는 `저장 완료`라고 표시하지 않는다. 폴더 연결이 끊기거나 쓰기에 실패하면 편집 내용을 보존하면서 `저장되지 않음`을 알리고 재연결·재시도를 제공한다. 다른 편집기로 `.md` 파일을 고친 경우에도 변경을 감지해 원문을 다시 읽고, 앱의 미저장 변경과 충돌하면 무조건 덮어쓰지 않는다. 기존 브라우저 저장 데이터는 사용자 확인을 거쳐 새 프로젝트 폴더로 옮기며 자동 이전·삭제하지 않는다.

현재 UI는 프로젝트 이름과 로컬 폴더를 선택한 뒤 채팅으로 이동하는 초판이다. 선택 정보는 새로고침 후에도 기억하지만, 이는 프로젝트 **내용**의 폴더 저장·복원을 뜻하지 않는다. 폴더 기능은 JSON 백업과 현재 문서 Markdown **내보내기**만 수행하며, 선택한 프로젝트 폴더의 내용을 앱이 다시 읽거나 자동 저장하지 않는다. 화면은 이 사실을 경고한다. 기존 테스트 데이터는 사용자가 명시적으로 초기화할 수 있지만 앱이 자동으로 삭제하지 않는다. 이 초기화 버튼은 개발 중 임시 수단이므로 폴더 정본 저장·데이터 전환이 완성되면 최종 프로젝트 화면에서 제거한다. 폴더 접근을 지원하지 않는 실행 환경에서는 브라우저 DB 저장을 폴더 저장인 것처럼 대체하지 않는다. 읽기 쉬운 문서 파일명, 버전 파일 배치, 보조 기록 형식, 원자적 쓰기·복구·충돌 규칙은 구현 전에 별도 저장 계약으로 확정한다.

### 문서 작성과 저장

`+ 새 연구노트`를 누르면 빈 초안 편집 화면을 연다. 처음에는 제목·큰 본문 편집 영역·`문서 저장`만 주 동작으로 제시하고, 중복 문서 목록·두 번째 `새 연구노트` 버튼·빈 분석 패널은 보이지 않는다. 최근 대화 답변 가져오기는 선택적 접기 영역에 둔다. 저장 후에만 `AI 분석`을 다음 단계로 보여 준다. 입력 예시는 짧게 보여 주되 가정·기호 등의 양식을 강요하지 않는다. 목표 저장 방식에서는 제목·본문을 프로젝트 폴더의 `.md` 파일에 저장해 새 정본 버전과 원문 위치를 만든다. 현재 구현은 브라우저 DB에만 저장하므로 폴더 저장으로 오해하지 않도록 화면에 명시한다. 편집 중에는 `미저장 변경`을 표시하고, 저장 오류가 나면 분석을 시작하지 않고 현재 편집 내용을 유지한다.

문서 삭제, 과거 버전 복원, 대화 답변에서 초안 만들기는 보조 메뉴에 둔다. 삭제는 대상 문서와 영향 범위를 읽을 수 있는 확인 절차를 유지한다. 버전 비교는 두 버전의 바뀐 부분을 문서 문맥에서 보여 준다.

### AI 분석 준비와 전송 승인

기본 분석 목표는 `논리적 빈틈과 모순 찾기`다. `핵심 주장 정리`, `정의·가정 찾기`, `외부 문헌과 대조`는 이후 선택할 수 있는 목적이지 처음부터 여러 버튼으로 나열하지 않는다. 분석 준비 화면은 다음 정보를 한 번에 보여 준다.

- 선택 모델과 요청 횟수, 가능한 범위의 예상 사용량. 금액 추정이 불가능하면 `비용 추정 불가`라고 표시한다.
- 이번에 보내는 제목·원문 구간·함께 보내는 자료의 파일명과 페이지. 전송하지 않는 문단·페이지와 그 이유.
- 긴 문서는 전체 구간 수와 현재 승인 대상 구간, 전체 분석을 마치기까지 추가 승인이 필요한 횟수. 조용히 잘라 보내지 않는다.
- 외부 문헌은 기본적으로 미포함. 사용자가 선택한 문헌의 추출문만 포함하고 PDF 원본 바이트는 보내지 않는다.

실행 승인 단위는 실제 전송 범위와 예상 요청 수가 고정된 한 묶음이다. 묶음 승인 기능을 제공할 경우 중지·실패·비용 상한을 먼저 명확히 해야 한다. 그전에는 요청마다 승인한다. 분석 중에는 현재 구간, 완료·남은 구간, 중단 버튼을 보여 준다. 중단·실패한 구간은 `미검사`로 남기고 자동 재전송하지 않는다. 한도가 부족해 전체를 다룰 수 없으면 시작 전에 `이번에 분석 가능한 범위`를 명확히 고른다.

### 결과 읽기와 수정

결과 첫 화면에는 전문 로그 대신 짧은 문서 요약, 가장 중요한 문제 카드, 분석 범위 표시를 둔다. 카드의 구조는 `무엇이 문제인가 → 문서의 어느 문장인가 → 왜 확인해야 하나 → 가능한 수정`이다. AI가 추출한 주장·가정·정의는 **후보**로 표시하고 원문 인용과 문서 위치를 붙인다. 인용 문자열 일치나 모델의 설명은 참·증명·독립 근거를 뜻하지 않는다.

문제 카드에서 `원문 보기`는 문서의 해당 문단을 강조한다. `수정안 비교`는 변경 전후와 새로 생길 수 있는 가정을 보여 준다. `적용`은 기존 정본을 덮어쓰지 않고 새 버전을 만든다. 사용자가 문서에서 직접 수정한 경우도 새 버전 저장 후 같은 재분석 흐름으로 돌아온다. `채택`, `보류`, `기각`은 후보의 사용자 판단을 기록할 때만 쓰고, 첫 결과를 읽는 데 필수로 만들지 않는다.

상단 범위 표시는 `현재 버전의 N개 구간 중 M개 분석`, `구간 간 종합 미수행`, `외부 문헌 대조 안 함`처럼 평이하게 쓴다. 어떤 부분도 검사하지 않은 경우 `문제 없음`을 표시하지 않는다. 이전 버전 결과는 명확히 `이전 버전의 결과`로 보이고 현재 문서 문제 목록에 무표시로 섞이지 않는다.

### 자료, 연구 기준, 그래프와 Wiki

자료는 `참고 문헌`과 `내 문서·메모`를 입력 시점부터 구분한다. 자체 문서를 다시 붙이면 계보를 연결해 동일 출처로 취급하며 외부 검증 수에 합산하지 않는다. 자료 추가 직후에는 로컬 추출 상태와 검색 가능 범위를 알려 준다. 텍스트가 없는 PDF는 `텍스트를 추출할 수 없음 · 검색에서 제외됨`으로 표시하고 사용자가 검색 가능한 사본을 준비하도록 안내한다. OCR은 제공하지 않는다. 암호화 PDF는 암호를 받지 않는다.

연구 기준은 결과에서 AI가 찾은 가정·정의·적용 범위 후보를 사용자가 확인하는 **선택적 정리 도구**다. 여섯 필드가 비어 있어도 저장과 첫 분석은 가능해야 한다. 필요한 기준을 채택하면 원문 위치와 문서 버전을 연결한다. 그래프는 주장·전제·정의 관계를 후보로 만들 수 있지만 사용자 확인 전에는 승인 관계처럼 쓰지 않는다. Wiki는 정본·승인된 항목·AI 후보를 상태별로 읽는 파생 화면이다. 어느 것도 독립된 외부 증거가 아니다.

## 상태와 문구의 공통 규칙

| 상태 | 사용자에게 보일 뜻 |
| --- | --- |
| 초안 또는 미저장 | 현재 편집 내용이 아직 정본 버전이 아님 |
| 폴더 연결 필요 / 저장 실패 | 프로젝트 자료에 접근하거나 쓸 수 없어 저장 완료가 아님 |
| 저장된 vN | 특정 버전이 정본으로 보존됨 |
| 전송 대기 | AI 요청 전이며 전송할 내용을 확인할 수 있음 |
| 분석 중 / 일부 완료 / 실패 / 중단 | 처리된 구간과 남은 구간을 별도로 표시 |
| 확인할 문제 | 모델 또는 구조 검사가 제안한 확인 사항이며 오류 확정이 아님 |
| 수정 후 재확인 필요 | 새 버전에서 이전 결과가 자동으로 유효하지 않음 |
| 사용자 확인 | 후보를 사람이 채택·기각한 기록이며 이론 검증 완료가 아님 |

`정합성 통과`, `증명됨`, `문제 없음` 같은 전면 판정은 사용하지 않는다. 내부 구조 검사, LLM의 논리 비평, 외부 문헌과의 호환성, 수학적 검증은 서로 다른 검사로 표시한다. 확인되지 않은 범위가 남으면 종료 화면에도 그대로 남긴다. 기술 ID·hash·요청 JSON·예산 세부값·관계 원장은 `검토 기록 자세히`에서 찾을 수 있게 하되 주 경로에 노출하지 않는다.

## 현재 구현과 바뀌어야 할 점

현재 앱은 처음 프로젝트 이름·로컬 폴더를 선택하면 채팅으로 이동하고, 선택 정보를 새로고침 뒤에도 기억한다. API 키가 없어도 채팅 화면을 먼저 보여 주고 설정은 사용자가 기존 안내에서 연다. 사이드바는 `+ 새 연구노트`, 문서 목록, `새 대화`, 기존 대화 기록, 레퍼런스·설정을 보여 준다. 새 문서는 전체 화면형 편집 화면에서 제목·본문·저장만 먼저 보여 주며, 저장한 뒤 AI 분석 패널이 나타난다. 문서 목록은 사이드바에만 두고, 연구 기준·프로젝트 정책·버전 비교 등은 저장 후 선택 도구에 둔다. 문서 화면에서 채팅 모드를 바꾸던 선택기는 제거했으며 문서별 모드 저장은 아직 구현되지 않았다. 선택한 폴더는 아직 프로젝트 데이터 경계나 `.md` 정본 저장에 사용되지 않고 연구노트 본문·버전은 브라우저 IndexedDB에 저장된다. 분석 결과에는 아직 기술 설명과 여러 승인 조작이 길게 이어진다. 새 화면과 데이터 기능을 혼동하지 않는다.

| 우선순위 | UI·UX 구현 작업 | 완료 확인 |
| --- | --- | --- |
| P0 | 프로젝트 시작 화면과 `.md` 정본·보조 기록의 로컬 폴더 저장 계약을 먼저 구현한다. 기존 테스트 데이터는 사용자 확인 후 정리할 수 있다 | 폴더만으로 문서 현재·이전 버전을 열 수 있고, 폴더 미연결·권한 거부·쓰기 실패·재연결·외부 편집 충돌에서 잘못된 `저장 완료`가 나오지 않음. 완성 후 임시 테스트 데이터 초기화 버튼 제거 |
| P0 | 채팅 화면과 대화 기록·레퍼런스 관리·설정을 유지하고, `+ 새 연구 세션`을 `+ 새 연구노트`로 교체한다. 별도 `연구노트` 버튼을 없앤다 | 프로젝트 선택 후 채팅이 열리고 버튼에서 현재 프로젝트의 새 문서로 이동 |
| P0 | 연구 특화 모드를 문서 작성·수정에 연결하고 모달을 독립 문서 작업 화면으로 옮긴다 | 연구 기준·자료·그래프 입력 없이 문서를 폴더에 저장하고 분석 준비에 도달 |
| P0 | 전송 확인을 사람이 읽는 범위·누락·비용·요청 수 중심으로 재구성하고 장문 중단/실패 상태를 표시한다 | 선택하지 않은 자료 미전송, 누락 없는 범위 표시, 자동 재전송 없음이 E2E로 확인 |
| P0 | 결과를 요약·문제 카드·원문 이동·수정 비교·재분석 중심으로 다시 배치한다 | 문제에서 원문과 새 버전으로 이동하고, 오래된 결과·미검사 범위를 구별할 수 있음 |
| P1 | 자료 선택을 문서 분석 안에 연결하고 내부/외부 출처를 분리해 표시한다 | 자체 문서를 독립 외부 근거로 표시하지 않음 |
| P1 | AI 주장·가정·관계 후보를 상태와 원문 위치가 있는 별도 데이터로 연결한다 | 후보/채택/기각이 섞이지 않고 Wiki도 같은 상태를 보여 줌 |
| P2 | 고급 그래프·검색·검토 기록·프로젝트 관리 화면을 주 경로와 분리해 정리한다 | 고급 기능을 유지하면서 첫 분석에 선행 입력을 요구하지 않음 |
| 후속 | 여러 연구노트로 논문 만들기의 별도 버튼과 작업 흐름을 사용자와 결정한다 | 문서 작성·검토의 P0 완료 조건에 섞지 않음 |

P0 화면이 실제로 작동하고 이해되는지 확인하기 전에는 기술 계층을 더 늘리지 않는다. 각 단계는 데스크톱 키보드 조작·포커스·폴더 권한 및 저장 실패·중단·빈 결과·장문 문서 시나리오를 포함해 lint, 단위 테스트, build, 핵심 Playwright E2E로 검증한다. 실제 API·실문헌 품질 평가는 별도 승인과 독립된 평가 자료가 필요하다. GitHub Actions와 배포는 보류한다.

## 사용자 확인이 필요한 설계 가설

첫 사용자가 문서를 올린 뒤 가장 먼저 보고 싶은 것은 `핵심 주장 정리`보다 `논리적 빈틈과 모순`이라는 가설을 기본값으로 두었다. 또한 데스크톱에서 문서와 문제를 나란히 보는 방식이 모달보다 수정 반복에 유리하다고 보았다. 두 가설은 구현 전에 간단한 정적 시안이나 클릭 가능한 프로토타입으로 확인하고, 실제 사용 피드백이 다르면 문구와 우선순위를 조정한다. 데이터 출처·전송 승인·버전 보존 원칙은 이 검증과 무관하게 유지한다.
